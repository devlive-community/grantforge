La 2026.2.0 estende le autorizzazioni dei sistemi esterni della 2026.1.0 ad Apache Hive, Apache Kafka, Apache HBase, Trino e Apache Hadoop YARN, con agenti che le applicano. L'elenco completo delle modifiche è nel [confronto su GitHub](https://github.com/devlive-community/grantforge/compare/v2026.1.0...v2026.2.0).

## Apache Hive

- Un plugin di servizio Hive: database, tabelle, colonne, UDF, URL, il servizio HiveServer2 e la replica, con i tipi di accesso di Hive come definiti da Apache Ranger; vedi [Apache Hive](/it/plugins/hive/).
- Un agente HiveServer2 che verifica ogni istruzione, filtra i risultati di `SHOW`, maschera le colonne e filtra le righe; vedi l'[agente Hive](/it/external/hive-agent/).
- Le UDF temporanee sono concesse a livello globale solo a `tempudfadmin`, come fa Apache Ranger, perché eseguono codice scelto dall'utente.

## Apache Kafka

- Un plugin di servizio Kafka: topic, gruppi, ID transazionali, il cluster, i token di delega e gli utenti SCRAM, con i tipi di accesso e le implicazioni propri di Kafka; vedi [Apache Kafka](/it/plugins/kafka/).
- Un autorizzatore di broker e controller che verifica ogni richiesta; vedi l'[agente Kafka](/it/external/kafka-agent/).

## Apache HBase

- Un plugin di servizio HBase: namespace, tabelle, famiglie di colonne e colonne, oltre al livello globale per le operazioni sull'intero cluster; vedi [Apache HBase](/it/plugins/hbase/).
- Un coprocessore per il master e i region server che verifica le operazioni, restituisce solo le colonne che un utente può leggere e nasconde ciò che non può vedere; vedi l'[agente HBase](/it/external/hbase-agent/).

## Trino

- Un plugin di servizio Trino: cataloghi, schemi, tabelle, colonne, funzioni, procedure e proprietà di sessione; vedi [Trino](/it/plugins/trino/).
- Due controlli di accesso di sistema, uno per Trino da 470 a 478 e uno per Trino 479 e successivi, che verificano le query, filtrano le righe e mascherano le colonne; vedi gli [agenti Trino](/it/external/trino-agent/).

## Apache Hadoop YARN

- Un plugin di servizio YARN: code e applicazioni, con i tipi di accesso `submit_app` e `admin_queue` di YARN; vedi [Apache Hadoop YARN](/it/plugins/yarn/).
- Un provider di autorizzazione nel ResourceManager che decide invio, code e amministrazione del cluster secondo la policy, con condizioni sugli indirizzi dei client; vedi l'[agente YARN](/it/external/yarn-agent/).

## Motore di policy e agenti

- Le policy decidono l'accesso a ciò che sta sotto una risorsa: elencare un database conta le policy sulle tabelle dell'utente, e il nuovo tipo di accesso `_any` è consentito quando è consentito un accesso sulla risorsa o al di sotto di essa.
- Le policy rispondono se un utente può fare qualcosa con una risorsa di un livello, come Kafka chiede prima che i producer idempotenti scrivano.
- Gli agenti raggruppano gli accessi consentiti identici di una finestra temporale in un unico evento di audit con un contatore e l'istante dell'ultimo; i rifiuti vengono registrati subito.
- Gli agenti possono mostrare le proprie policy di accesso nei termini del sistema stesso.
- L'API dei plugin 1.2.0 fornisce i realm Kerberos una sola volta a tutti i plugin, che non sovrascrivono più a vicenda il loro `krb5.conf`.

## Documentazione e pubblicazione

- I plugin e gli agenti di YARN, Hive, Kafka, HBase e Trino sono documentati in tutte e undici le lingue.
- Il README elenca i componenti supportati e le versioni verificate dai test di integrazione.
- I tag di rilascio eseguono la CI completa e la pubblicazione attende quell'esecuzione; la distribuzione è compilata in parallelo; npm pubblica tramite trusted publishing.
- Le release senza il relativo registro di rilascio vengono rifiutate al tag; dopo un gate Java comune, la CI esegue solo i job di cui una modifica ha bisogno.

## Correzioni

- Gli indici PostgreSQL vengono preparati dopo il caricamento dei dati, così le chiamate API cronometrate girano su tabelle analizzate.
- I test dei jar dell'agente ZooKeeper vengono eseguiti dopo il packaging.
- I deploy Maven saltano i test di integrazione; un timeout della JVM forkata sull'agente HDFS 3.2 aveva fatto fallire il deploy su GitHub Packages.
- Il pacchetto npm dichiara il proprio repository, così npm può verificare la provenance.
