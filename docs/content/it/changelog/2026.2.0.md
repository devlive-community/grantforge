La 2026.2.0 estende le autorizzazioni dei sistemi esterni della 2026.1.0 ad Apache Hive, Apache Kafka, Apache HBase, Trino e Apache Hadoop YARN. Ogni sistema dispone di un plugin di servizio e di un agente che applica le sue policy. L'elenco completo delle modifiche è nel [confronto su GitHub](https://github.com/devlive-community/grantforge/compare/v2026.1.0...v2026.2.0).

## Apache Hive

- Plugin di servizio Hive: ricerca di database, tabelle, colonne e UDF, con accesso tramite password o Kerberos; vedi [Apache Hive](/it/plugins/hive/).
- Agente HiveServer2: autorizza ogni istruzione, filtra i risultati di `SHOW`, maschera le colonne e filtra le righe; vedi [Agente Hive](/it/external/hive-agent/).
- Le UDF temporanee sono concesse nell'ambito globale solo a `tempudfadmin`, come in Apache Ranger, perché eseguono codice scelto dall'utente.

## Apache Kafka

- Plugin di servizio Kafka: ricerca di topic, gruppi di consumer, ID transazionali e utenti, con accesso tramite PLAIN, SCRAM o Kerberos, in chiaro o TLS; vedi [Apache Kafka](/it/plugins/kafka/).
- Autorizzatore per broker e controller: verifica ogni richiesta, mostra le policy come ACL di sola lettura e raggruppa gli accessi ripetuti in un unico evento di audit; vedi [Agente Kafka](/it/external/kafka-agent/).

## Apache HBase

- Plugin di servizio HBase: ricerca di namespace, tabelle e column family, tramite ZooKeeper o server di bootstrap, in modo semplice o con Kerberos; vedi [Apache HBase](/it/plugins/hbase/).
- Coprocessore per master e region server: verifica operazioni, letture e scritture a ogni ambito, restituisce solo le colonne leggibili dall'utente e nasconde ciò che l'utente non può usare; vedi [Agente HBase](/it/external/hbase-agent/).

## Trino

- Plugin di servizio Trino: ricerca di catalog, schemi, tabelle, colonne e proprietà di sessione, con accesso tramite password, JSON Web Token o Kerberos su TLS; vedi [Trino](/it/plugins/trino/).
- Due controlli di accesso di sistema: uno per Trino 470-478 e uno per la 479 e successive. Verificano le query, elencano solo ciò che l'utente può usare, filtrano le righe e mascherano le colonne; il secondo verifica anche i branch delle tabelle e l'aggiornamento delle view; vedi [Agente Trino](/it/external/trino-agent/).

## Apache Hadoop YARN

- Plugin di servizio YARN: connessione a un ResourceManager o a una coppia ad alta disponibilità, in modo semplice o con Kerberos, e ricerca di code e nomi di applicazioni; vedi [Apache Hadoop YARN](/it/plugins/yarn/).
- Provider di autorizzazione nei ResourceManager: decide per policy chi può inviare, in quali code e l'amministrazione del cluster, con condizioni sugli indirizzi dei client; vedi [Agente YARN](/it/external/yarn-agent/).

## Motore di policy e agenti

- Le policy decidono l'accesso a qualsiasi risorsa di un livello e a ciò che si trova sotto una risorsa; quindi, quando si elenca un database, contano anche le policy sulle tabelle dell'utente.
- Gli agenti che verificano ogni richiesta raggruppano gli accessi consentiti identici di una finestra temporale in un evento di audit con il conteggio e il momento dell'ultimo; i rifiuti vengono registrati subito.
- Gli agenti possono mostrare le proprie policy di accesso nei termini del sistema in cui operano.

## Documentazione e rilascio

- La documentazione dei plugin e agenti di YARN, Hive, Kafka, HBase e Trino è disponibile in undici lingue.
- Il README elenca i componenti supportati e le versioni verificate dai test di integrazione.
- La CI esegue, dopo un gate Java comune, solo i job necessari a ogni modifica, e rifiuta un tag senza il registro di rilascio.

## Correzioni

- Gli indici PostgreSQL vengono preparati dopo il caricamento dei dati, così le chiamate API cronometrate girano su tabelle analizzate.
- I test del jar dell'agente ZooKeeper vengono eseguiti dopo il packaging.
