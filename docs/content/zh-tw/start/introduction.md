GrantForge 是一個開源（MIT）的統一權限平台。它把「誰能做什麼、能看到哪些資料」集中管理起來：在主控台裡維護使用者與組織、定義角色、給角色授予選單、按鈕、API、資料列與欄位；你的應用程式則透過 OAuth 2.1 / OpenID Connect 讓使用者登入，再以開放 API 或 SDK 判斷權限。

![GrantForge 主控台概覽](/screenshots/dashboard.png)

## 它解決什麼問題

一個系統做到一定規模，權限往往散落在各處：選單寫在前端設定裡，介面各自用註解檢查，資料範圍靠 SQL 裡手寫的條件，離職、職務調動時沒人說得清一個人到底還能做什麼。GrantForge 把這些統一到一個模型裡：

- **一處定義，到處生效**：主控台頁面、按鈕、REST 介面、資料實體與欄位都是「資源」，角色對資源授權，同一份授權同時驅動前端的顯示隱藏與後端攔截。
- **看得見的權限**：任何時候都能回答「他為什麼能看到這個頁面」「改了這個角色會影響誰」，授權變更有所預覽、有稽核。
- **符合治理要求**：職責分離、限時的權限申請、定期覆核、兩步驟驗證，滿足等級保護與內控稽核的常見要求。
- **以標準協定串接**：應用程式不必內嵌一套使用者體系，用 OIDC 登入、用存取權杖查詢權限即可。

## 功能一覽

| 領域 | 功能 |
| --- | --- |
| 身分與組織 | 多租戶、部門樹、使用者群組、職位；CSV 批次匯入匯出；LDAP/AD 登入與同步、OIDC 聯合登入 |
| 帳號安全 | 會話管理、密碼策略與鎖定、TOTP 兩步驟驗證與還原碼、敏感操作二次驗證 |
| 功能授權 | 資源目錄（模組、選單、頁面、標籤、按鈕、API）、角色繼承、授權矩陣、影響分析 |
| 資料權限 | 依條件限定可見的資料列（本人、所屬部門及其下級、指定部門、自訂條件），讀寫分開控制 |
| 欄位權限 | 隱藏、遮罩（電子郵件、手機號碼、證件號碼等）或唯讀欄位 |
| 可解釋與稽核 | 權限解釋、授權模擬、稽核日誌查詢與匯出 |
| 治理 | 職責分離約束、權限申請與核准、定期權限覆核 |
| 應用程式整合 | OAuth 2.1 / OIDC 授權伺服器、權限查詢開放 API、Java（Spring Boot）與 JavaScript SDK |
| 外部系統 | 外掛化服務類型與策略引擎（類似 Apache Ranger）、資料服務、存取策略與代理 |
| 交付 | 單一發行包、Docker 映像、Compose 範例、Helm Chart；H2、PostgreSQL、MySQL、MariaDB、Oracle、SQL Server |

## 與常見方案的差異

> [!NOTE]
> GrantForge 不是一個僅做 RBAC 的函式庫，也不是僅做單點登入的 IdP。它把身分、授權與治理放在同一個模型裡，並讓每一項授權都可以被解釋。

- **與在程式碼中手寫權限相比**：權限規則在主控台維護，變更授權不需要發佈應用程式；授權前能看到影響範圍，授權後有稽核。
- **與僅做認證的 IdP（Keycloak 等）相比**：GrantForge 自帶精細到按鈕、資料列與欄位的授權模型，以及職責分離、覆核等治理功能；同時也能作為 IdP，或者把既有的 LDAP、OIDC 作為身分來源串接。
- **與 Apache Ranger 相比**：GrantForge 借鏡 Ranger 的服務類型、策略與代理架構，用於管理外部資料系統的權限；同時它首先是一個業務應用程式的權限平台。
