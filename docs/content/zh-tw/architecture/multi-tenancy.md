## 隔離方式

除平台共享的資料外，每張業務資料表都有 `tenant_id` 欄位。請求進入時，過濾鏈把登入帳號所屬的租戶繫結到目前的執行緒，Hibernate 的租戶過濾器自動為查詢加上租戶條件，寫入時自動填入 `tenant_id`。業務程式碼無法「忘記」加上租戶條件。

需要跨租戶的少數情境（例如登入時依使用者名稱尋找帳號、統計各租戶的帳號數、後台定時任務）必須顯式進入「系統上下文」，程式碼審查可以一眼找到它們。

## 共享與獨立

| 平台共享 | 每個租戶獨立 |
| --- | --- |
| 應用程式與資源目錄、API 目錄、OAuth 用戶端、外掛程式 | 帳號、部門、使用者群組、職位、角色、授權、指派、資料與欄位政策、職責分離、申請與覆核、身分來源、資料服務、稽核 |

使用者名稱在整個平台內唯一，因此登入時不需要選擇租戶。

## 平台租戶

平台租戶由初始化建立，不能停用。它的管理員管理平台共享的資料與其他租戶；只有平台租戶的角色可以使用「全部租戶」的資料範圍。

## ID

所有主鍵都是 TSID：64 位元、依時間排序、在叢集中由節點編號保證唯一。它們大於 JavaScript 能精確表示的整數，因此在 JSON 中一律以字串傳遞。叢集中每個執行個體需要不同的 `GRANTFORGE_ID_NODE`。
