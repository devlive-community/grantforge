本文描述求值的精確規則。概念入門見 [核心概念](/zh-tw/start/concepts/)。

## 資源樹與型別

資源屬於某個應用程式，以樹狀組織，最多 15 層。型別決定它可以放在哪裡：

| 型別 | 允許的父層 |
| --- | --- |
| 模組 | 頂層、模組 |
| 選單、頁面 | 頂層、模組、選單 |
| 標籤 | 頁面、標籤 |
| 按鈕 | 頁面、標籤 |
| API、資料實體 | 頂層、模組 |
| 欄位 | 資料實體 |

資源之間可以宣告相依：「必需」（授予資源時一併授予被相依的資源）或「可選」（僅提示管理員，不自動授予）；相依不能成環。主控台的頁面、按鈕與它們需要的 API 由前端的權限清單宣告，伺服器端啟動時同步為內建資源。

## 授權推導

對一個帳號，求值器先確定**有效角色**：

1. 直接指派給帳號的角色；
2. 指派給帳號所屬的使用者群組、部門（包含「含下級」的上級部門所做的指派）、所任職位的角色；
3. 僅取目前時間在有效期內的指派，以及已啟用的角色；
4. 展開繼承：一個角色的全部祖先角色（停用的祖先不傳遞）。

再合併這些角色的授權：

- 允許一個資源，等於允許它本身、它在樹上的祖先（使其可見），以及它「必需」相依的資源（遞迴）。
- 拒絕一個資源，作用於它與其全部下級，並且**優先於任何允許**。
- 停用的資源及其下級不生效。
- 系統角色等同於允許其模組（如 `system`、`data`、`platform`）的整棵子樹。

結果是可用資源的集合，以及其中 API 資源對應的權限碼。

## 越權防護

- 授予「允許」時，授予者自己必須能使用該資源（持有系統角色的人對業務應用程式不受此限）。
- 指派角色或設定繼承時，授予者必須涵蓋該角色在各應用程式中涵蓋的全部資源。
- 平台管理員角色只能由目前的持有者指派、修改或移除。
- 「拒絕」不受限制：任何具有授權權限的人都可以收緊權限。

## 資料規則

資料政策屬於角色，以「實體 × 動作 × 效果」定義範圍：`ALL`（僅平台租戶）、`TENANT`、`ORG_AND_CHILDREN`、`ORG`、`CUSTOM_ORGS`、`SELF`、`CONDITION`。一列資料可用，當且僅當它符合至少一條允許規則，且不符合任何拒絕規則。

條件是結構化 JSON，不可執行，先驗證再寫入資料庫：

```json
{ "and": [
  { "field": "status", "op": "eq", "value": "ACTIVE" },
  { "not": { "field": "orgUnitId", "op": "in", "value": { "var": "subject.orgUnitIds" } } }
] }
```

變數僅有 `subject.id`、`subject.username`、`subject.orgUnitIds`、`subject.groupCodes`、`subject.positionCodes` 與 `now`；比較運算子依欄位型別限定；巢狀深度不超過 5 層、節點不超過 50 個。伺服器端把規則翻譯成 JPA `Specification`，SDK 以相同的語義在業務應用程式裡翻譯。

## 欄位規則

欄位政策給出讀取方式（可見、遮罩、隱藏）與寫入方式（可編輯、唯讀），多個角色取最寬鬆的設定，沒有任何設定時欄位完全開放。讀取規則在 JSON 序列化時執行（同一個 DTO 在不同人面前呈現不同），寫入規則在服務層執行，修改唯讀欄位會回傳 `GF-FIELD-001` 並指出欄位。

## 快照與版本

求值結果是一個**權限快照**：可用資源、權限碼、資料規則與欄位規則。快照按帳號快取；授權、指派、繼承、資源目錄、政策、成員關係的任何變更都會提升所在範圍（目錄或租戶）的版本號，使快取失效。每個需要權限的介面在回應標頭 `X-Authorization-Version` 中回傳目前版本，主控台據此判斷是否需要重新載入選單；開放 API 以 ETag 表達同樣的版本。
