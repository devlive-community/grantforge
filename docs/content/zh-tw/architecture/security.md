## 主控台工作階段

- 工作階段儲存在資料庫（Spring Session JDBC），瀏覽器只持有 `GRANTFORGE_SESSION` Cookie：HttpOnly、SameSite=Lax，HTTPS 下帶 Secure（或以 `grantforge.security.cookie-secure` 強制）。
- 登入、完成雙因素驗證、完成聯合登入時都會更換工作階段 ID 與 CSRF 權杖，以防工作階段固定。
- 狀態修改請求必須帶 `X-XSRF-TOKEN` 標頭，值來自 `XSRF-TOKEN` Cookie。
- 管理員可以列出並結束任何工作階段；停用、鎖定、重設密碼會立即結束該帳號的全部工作階段；變更密碼會結束其他裝置上的工作階段。

## 密碼

- 新密碼以 Argon2id 雜湊；BCrypt 與從 1.x 匯入的雜湊仍可驗證，並會在下次登入時升級為目前的演算法。
- 政策：長度、字元類別、歷史記錄、有效期都可以設定，密碼不能包含使用者名稱。
- 連續失敗達到次數後鎖定帳號；對未知的使用者名稱也會執行一次雜湊比對，因此回應時間不會暴露哪些使用者名稱存在；停用的帳號與停用的租戶只有在密碼驗證通過後才會回報。

## 雙因素驗證與再次驗證

- TOTP（RFC 6238，SHA-1、6 位數、30 秒，前後各容忍一個時間步），同一個時間步的驗證碼只能使用一次；10 組一次性的還原碼以 SHA-256 儲存。
- 已開啟雙因素驗證的帳號，密碼正確後工作階段會處於「待完成」狀態 5 分鐘，在完成第二步之前不算已登入。
- 敏感介面以 `@RequireStepUp` 標註：已開啟雙因素驗證的帳號必須在可設定的時間窗內驗證過，否則回傳 `GF-SECURITY-006`，主控台跳出對話框確認後重試。

## 加密儲存

身分來源的繫結密碼與用戶端密鑰、驗證器金鑰、資料服務的敏感設定、授權伺服器的簽章私鑰，都以 AES-GCM 加密後儲存。金鑰來自 `grantforge.security.encryption-key`；未設定時會自動產生並儲存在資料庫中（僅適合試用）。代理權杖與 OAuth 用戶端密鑰只儲存雜湊。

## 權杖

- 授權伺服器保存權杖的雜湊，而不是權杖本身。
- 重新整理權杖每次使用都輪替，舊權杖被重放時會撤銷整個授權。
- 帳號停用、鎖定、要求變更密碼，用戶端停用，租戶停用，都會阻止權杖續期；開放 API 每次呼叫都會再次確認權杖仍然有效。
- 政策快照以 Ed25519 簽章，代理驗證簽章後才使用。

## 介面防護

- 每個介面都必須宣告存取方式，沒有宣告的介面無法啟動；需要權限的介面在每次呼叫時依最新的快照檢查。
- 被拒絕的呼叫會寫入稽核（不阻塞請求）。
- 外部身分來源的同名本機帳號不會被自動關聯，以防帳號被接管。
- 匯出 CSV 時，以 `=`、`+`、`-`、`@` 開頭的儲存格會加上前綴，以防公式注入。

## 稽核

所有管理操作、授權變更、登入事件與被拒絕的呼叫都記錄在稽核日誌中；權限相關的變更與它的稽核在同一個交易內提交，變更回復時稽核也不會留下。
