資料權限決定角色的持有者能讀取、修改、刪除、匯出各類資料中的**哪些列**。在角色列上點擊 **資料權限** 進行設定。

![資料權限](/screenshots/role-data.png)

## 規則

每條規則由四部分組成：

| 部分 | 選項 |
| --- | --- |
| 資料實體 | 使用者、部門、使用者群組、職位、稽核事件，以及業務應用程式宣告的實體（如 `shop:order`） |
| 動作 | 檢視、修改、刪除、匯出 |
| 範圍 | 全部租戶（僅平台租戶的角色）、本租戶全部、本部門及下級、本部門、指定部門、僅本人、依條件 |
| 效果 | 允許或拒絕 |

合併規則：

- **沒有任何允許的規則時看不到資料。**
- **拒絕優先於允許**：命中任何一條拒絕規則的列都不可用。
- 一個人的多個角色的規則一起生效：允許取聯集，拒絕同樣取聯集。
- 系統角色隱含相應的範圍（租戶管理員是本租戶全部），業務應用程式的實體除外。

## 依條件

範圍選「依條件」時，用條件編輯器組合條件：

- 比較實體的欄位，例如「狀態 等於 正常」「最近登入 早於 目前時間」。文字支援包含、開頭是；數字和時間支援大小比較；還支援屬於、不屬於、為空、不為空。
- 值可以是固定值，也可以是**目前使用者的屬性**：本人 ID、使用者名稱、所屬部門、所屬使用者群組、所任職位，以及目前時間。
- 條件可以用「全部符合 / 任一符合」分組，可以否定，最多巢狀 4 層。

## 預覽

在編輯器裡選擇一個使用者點擊 **預覽**，可以看到這個角色的規則讓他能看到多少列，以及具體是哪些。

## 在哪裡生效

主控台的使用者、部門、使用者群組、職位清單與詳情、匯入匯出、稽核日誌都遵守資料權限；看不到的列在清單中不出現，直接以 ID 存取也回傳「不存在」。業務應用程式透過 [Java SDK](/zh-tw/integration/java/) 或 [開放 API](/zh-tw/integration/open-api/) 取得同樣的規則。
