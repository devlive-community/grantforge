**存取控制 → 身分來源** 設定使用者可以用來登入的目錄或身分提供者。這類帳號的密碼儲存在身分來源裡，GrantForge 不儲存也不能修改它們。

![身分來源](/screenshots/identity-sources.png)

## LDAP / Active Directory

點擊「新增身分來源」，類型選「LDAP 目錄」：

| 設定 | 說明 |
| --- | --- |
| 目錄位址 | `ldap://` 或 `ldaps://`，多個位址以空格分開實作故障切換 |
| 使用者所在 Base DN | 例如 `ou=people,dc=example,dc=com` |
| 查詢帳號 | 用來尋找使用者的帳號（Bind DN）及其密碼；留空則匿名查詢 |
| 使用者過濾條件 | 預設 `(&(objectClass=person)(uid={0}))`，`{0}` 是使用者輸入的名字 |
| 屬性 | 使用者名稱、顯示名稱、電子郵件、唯一識別的屬性；預設相容 OpenLDAP（`uid`、`cn`、`mail`、`entryUUID`），Active Directory 請填 `sAMAccountName` 與 `objectGUID` |
| 為新使用者自動建立帳號 | 開啟後，目錄裡的使用者首次登入即建立帳號 |
| 同步間隔 | 留空則僅手動同步，最短 15 分鐘 |
| 停用已離開目錄的使用者帳號 | 同步時停用目錄中已不存在的使用者 |

儲存後點擊 **測試連線** 確認設定正確。

登入時，GrantForge 先用查詢帳號找到使用者，再用使用者輸入的密碼、以該使用者的身分繫結目錄來驗證密碼。

**同步**會為目錄中的新使用者建立帳號、更新既有帳號的姓名與電子郵件，並依設定停用已離開的使用者（同時結束他們的工作階段）。同步結果顯示在身分來源卡片上。

## OpenID Connect

類型選「OpenID Connect」，可以接入 Keycloak、Azure AD、Okta、另一套 GrantForge 等：

| 設定 | 說明 |
| --- | --- |
| Issuer 位址 | 提供者的簽發者位址，GrantForge 透過它的發現文件取得端點與金鑰 |
| 客戶端 ID / 金鑰 | 在提供者註冊的客戶端；沒有金鑰時作為公開客戶端，使用 PKCE |
| 回呼位址 | 頁面上顯示的 `<GrantForge>/api/v1/auth/federated/callback/<編碼>`，需要註冊到提供者的客戶端裡 |
| 範圍與宣告 | 預設 `openid profile email`；使用者名稱、顯示名稱、電子郵件分別取 `preferred_username`、`name`、`email` 宣告 |
| 手機號碼宣告 | 預設讀取 `phone`（Casdoor）；其他提供者可設定為 `phone_number`。要同步手機號碼，scope 需包含 `phone`。登入時若提供者未回傳號碼，保留既有號碼 |
| 頭像位址 | 從 OIDC 標準 `picture` 宣告同步，scope 需包含 `profile`；未回傳時保留既有頭像位址 |
| 授權請求附加參數 | 選填的 JSON 物件，值必須為字串。例如 Casdoor 可填寫 `{"provider_hint":"github"}`，指定已設定的提供者；參數會出現在瀏覽器網址中，請勿填寫金鑰 |

協定關鍵參數（包括 `state`、`nonce`、`redirect_uri` 與 PKCE 參數）由 GrantForge 管理，無法透過附加參數覆寫。

啟用後，登入頁出現「透過 <名稱> 登入」按鈕。使用者在提供者登入後回到 GrantForge；已開啟雙因素驗證的帳號還要輸入驗證碼。

## 帳號規則

- 身分來源使用者的唯一識別（LDAP 的 `entryUUID`/`objectGUID`、OIDC 的 `sub`）對應一個 GrantForge 帳號，改名不影響對應關係。
- 本地已有同名帳號時**不會自動關聯**，登入會被拒絕，需要管理員先改名或刪除本地帳號。這可避免目錄裡的同名使用者接管既有帳號。
- 不會自動建立帳號的身分來源僅能讓已關聯的使用者登入。
- 停用身分來源後，它的使用者無法登入；仍有帳號在使用的身分來源不能刪除。
- 身分來源帳號可以照常指派角色、開啟雙因素驗證。

組織架構同步在獨立的資料來源中設定，不需要修改 OIDC 登入設定。

## 資料來源與組織架構同步

資料來源負責組織架構同步，身分來源繼續負責 OIDC 或 LDAP 登入。兩者獨立設定，停用資料來源不影響 OIDC 登入。

1. 在「存取控制 → 身分來源」中設定現有的 OpenID Connect 登入。
2. 在「存取控制 → 資料來源」中新增釘釘資料來源，選擇關聯的 OIDC 身分來源。
3. 填寫 CorpId、AppKey、AppSecret 與起始部門 ID（通常為 `1`）。AppSecret 單獨加密保存，介面不會回傳明文，編輯時留空即保留原值。
4. 可掛載到本地部門；同步間隔預設 30 分鐘，允許 15–10080 分鐘，清空表示只手動同步。
5. 儲存後測試連線並執行首次同步。釘釘應用程式需有部門及員工通訊錄讀取權限，其授權範圍應涵蓋所選子樹。
6. 使用者透過 SSO 登入後，依可信的 OIDC 電子郵件比對員工，自動填入部門與主部門。電子郵件必須由管理員維護、員工無法自行冒用，並與釘釘電子郵件一致。員工電子郵件缺失時使用企業電子郵件。

登入只讀取本地通訊錄快照，不請求釘釘。開啟 MFA 時，在第二步驗證成功後才更新歸屬。首次同步前登入的帳號會暫存可信電子郵件，同步完成後再補上關聯；本地可編輯的個人資料電子郵件不參與比對。缺失、重複或已被其他帳號綁定的電子郵件不會建立新綁定。

員工綁定以外部員工 ID 保持穩定，不會因電子郵件變更而轉移到另一位員工。同步涵蓋多部門歸屬；主部門優先保留仍有效的原主部門，否則依穩定的部門 ID 順序選擇。本地部門、使用者群組、職位與直接角色授權都會保留。將角色指派給同步部門後，使用者依現有授權規則繼承角色，調動部門會更新權限。

已有組織快照或待關聯帳號後，關聯的身分來源、企業、應用程式、起始部門與掛載位置即固定。同步的部門與歸屬為唯讀，無法從使用者或組織管理中手動覆寫。消失的部門會保留，以保護既有授權；員工離開授權通訊錄後，移除此資料來源管理的歸屬，但不會自動停用帳號。擁有同步部門的資料來源不能直接刪除，可改為停用。

同步取得完整分頁後再以原子方式套用。讀取失敗、層級異常或授權範圍變化時保留上次成功的快照，管理員可透過同步摘要、異常清單與稽核記錄檢查結果。授權範圍變化時，需先恢復原本核准的範圍再同步。

目前使用[釘釘官方服務端 SDK](https://open.dingtalk.com/document/development/download-the-server-side-sdk)，沒有自行實作 HTTP 呼叫。供應商配接器輸出統一的部門與員工快照，之後可增加飛書配接器，重用相同的同步、綁定與權限更新邏輯。
