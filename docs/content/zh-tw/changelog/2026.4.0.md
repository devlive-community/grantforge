2026.4.0 將外部系統權限擴充到 Elasticsearch、Apache Doris、MongoDB 以及 Redis 與 Valkey，四個代理都在系統旁執行，讓系統自身的存取控制與策略保持一致。身分與授權方面新增釘釘組織架構同步、使用者直接授權與資源目錄的匯入匯出。完整變更見 [GitHub 比較](https://github.com/devlive-community/grantforge/compare/v2026.3.0...v2026.4.0)。

## Elasticsearch

- Elasticsearch 服務外掛：索引與資料串流、其欄位以及叢集；支援密碼、API 金鑰或 TLS 用戶端憑證登入；見 [Elasticsearch](/zh-tw/plugins/elasticsearch/)。
- 在叢集旁執行的代理：為每位使用者維護 Elasticsearch 自己的角色，賦予原生使用者，並透過角色對應給其他 realm 的使用者；授權許可允許時帶有欄位層級與文件層級安全性；索引模式保持為模式，新索引立即可用；見 [Elasticsearch 代理](/zh-tw/external/elasticsearch-agent/)。
- 存取記錄來自稽核日誌檔案。整合測試涵蓋 Elasticsearch 8.19、9.3、9.4 與 9.5。

## Apache Doris

- Doris 服務外掛：Catalog、資料庫、資料表、欄位與工作負載群組；連線一個或多個 FE，以密碼登入；見 [Apache Doris](/zh-tw/plugins/doris/)。
- 在叢集旁執行的代理：策略成為 Doris 自己的角色、欄位授權、工作負載群組授權與資料列策略，並授予使用者的每個身分；只有在 Doris 不會因此給出更多權限時，才授予整個資料庫或 Catalog；見 [Apache Doris 代理](/zh-tw/external/doris-agent/)。
- 存取記錄來自 Doris 的稽核日誌表。整合測試涵蓋 Doris 2.1、3.1、4.0 與 4.1。

## MongoDB

- MongoDB 服務外掛：資料庫與集合；連線副本集或分片叢集，支援 SCRAM、用戶端憑證、LDAP 或 Kerberos 登入；見 [MongoDB](/zh-tw/plugins/mongodb/)。
- 在部署旁執行的代理：為每位使用者維護一個 MongoDB 角色，一步替換其權限；透過 MongoDB 提供的繼承權限，回報 GrantForge 之外的內建與自訂角色實際給了什麼；見 [MongoDB 代理](/zh-tw/external/mongodb-agent/)。
- 存取記錄來自 Enterprise 或 Percona 的稽核日誌檔案，或來自 Profiler。整合測試涵蓋 MongoDB 6.0、7.0、8.0 與 9.0，Kerberos 在 Percona Server for MongoDB 上驗證。

## Redis 與 Valkey

- Redis 服務外掛：鍵、頻道與節點；連線單機及其副本或叢集，以 ACL 使用者登入，可選 TLS；見 [Redis](/zh-tw/plugins/redis/)。
- 在部署旁執行的代理：在每個節點上讓每位使用者的 ACL 選擇器與策略保持一致，並以一條命令整體替換；根權限仍由維運人員管理，代理以 `ACL DRYRUN` 詢問 Redis 這些權限是否允許了策略拒絕的存取；見 [Redis 代理](/zh-tw/external/redis-agent/)。
- 拒絕記錄來自各節點的 ACL 日誌。整合測試涵蓋 Redis 7.2、7.4、8.2、8.10 與 Valkey 8.1、9.1，以及一個 Redis 8.10 叢集。

## 代理

- ClickHouse、PostgreSQL、OpenSearch 以及本版新增的系統旁代理共用新的 `grantforge-agent-sync` 核心：啟動器、設定、計時器、同步流程、稽核讀取位置與日誌檔案追蹤；各代理只保留其系統特有的部分，設定與日誌格式不變。

## 身分與組織

- 資料來源：組織架構同步獨立於身分來源設定，首個配接器為釘釘，使用其官方服務端 SDK；使用者透過 SSO 登入後依可信電子郵件自動關聯部門與主部門；其資料表在全部六種支援的資料庫上遷移，包括 SQL Server 與 Oracle；見 [身分來源（LDAP 與 OIDC）](/zh-tw/guide/identity-sources/)。
- OpenID Connect 身分來源可以同步手機號碼與頭像，並可在授權請求中附加參數（例如 Casdoor 的 `provider_hint`），協定自身的參數無法被覆寫。

## 授權與資源目錄

- 使用者直接授權：為單一使用者允許業務應用程式的選單、頁面、按鈕或介面，可設定到期時間，與角色權限一起計算，角色中的拒絕仍然優先；見 [使用者](/zh-tw/guide/users/)。
- 資源目錄可以把應用程式的資源樹匯出為 JSON，再匯入另一個應用程式：先預檢，衝突時整個匯入不生效；平台管理員可以清空符合條件的應用程式資源樹；見 [資源目錄與 API 目錄](/zh-tw/guide/catalog/)。

## 服務端

- 啟動時印出 GrantForge 的橫幅、版本與 Java 版本，不再是 Spring Boot 的橫幅。

## 文件與發布

- 外掛頁以總覽開始，依系統類型分組並可摺疊，列出每個系統的執行方式、資料列過濾與遮罩支援以及驗證過的版本；各 README 依同樣的順序列出元件。
- CI 檢查每個頁面在每種語言中的翻譯是否完整：段落、標題、表格、程式碼區塊與連結與中文頁一致，不含其他語言的文字，也不照抄英文頁；11 個 README 依英文 README 做同樣的檢查。檢查發現的缺漏翻譯已全部補齊。
- 所有 README 的版本徽章都由版本檢查維護。
- 在 fork 上不再執行發布文件與發布版本的工作流程。
- 服務端 `grantforge-server` 不再發布到 Maven 儲存庫：它包含全部外掛，超出了儲存庫的大小限制；服務端隨發行包與映像提供。

## 問題修正

- 在資源編輯框中改變資源類型時，清除不再適用的資源編碼。
- JavaScript 接入指南的最後一個程式碼區塊不再吞掉後面的內文，Docker 與快速開始頁面中的主控台位址不再把後面的文字當作連結。
- 相依套件升級到修正安全公告的版本：MariaDB Connector/J 3.5.11、OpenTelemetry 1.67.0、Guava 33.7.2、Snappy 1.1.10.9，以及主控台與 SDK 中的 vue-i18n、glob 與 minimatch。
