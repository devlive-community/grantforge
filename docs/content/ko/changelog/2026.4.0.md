2026.4.0은 외부 시스템 권한을 Elasticsearch, Apache Doris, MongoDB, Redis와 Valkey로 확장합니다. 네 에이전트 모두 시스템 옆에서 실행되며 시스템 자체의 접근 제어를 정책과 일치시킵니다. 신원과 인가 쪽에서는 DingTalk 조직 구조 동기화, 사용자 직접 권한 부여, 리소스 카탈로그 내보내기와 가져오기가 추가되었습니다. 전체 변경 사항은 [GitHub 비교](https://github.com/devlive-community/grantforge/compare/v2026.3.0...v2026.4.0)를 참고하십시오.

## Elasticsearch

- Elasticsearch 서비스 플러그인: 인덱스와 데이터 스트림, 그 필드, 클러스터. 비밀번호, API 키 또는 TLS 클라이언트 인증서로 로그인합니다. [Elasticsearch](/ko/plugins/elasticsearch/)를 참고하십시오.
- 클러스터 옆에서 실행되는 에이전트: 사용자마다 Elasticsearch 자체 역할을 유지해 네이티브 사용자에게 부여하고, 다른 realm의 사용자에게는 역할 매핑으로 부여합니다. 라이선스가 허용하면 필드 수준과 문서 수준 보안도 붙입니다. 인덱스 패턴은 패턴으로 유지되어 새 인덱스에도 바로 접근할 수 있습니다. [Elasticsearch 에이전트](/ko/external/elasticsearch-agent/)를 참고하십시오.
- 접근 기록은 감사 로그 파일에서 가져옵니다. 통합 테스트는 Elasticsearch 8.19, 9.3, 9.4, 9.5를 다룹니다.

## Apache Doris

- Doris 서비스 플러그인: 카탈로그, 데이터베이스, 테이블, 열, 워크로드 그룹. 하나 이상의 FE에 연결하고 비밀번호로 로그인합니다. [Apache Doris](/ko/plugins/doris/)를 참고하십시오.
- 클러스터 옆에서 실행되는 에이전트: 정책은 Doris 자체 역할, 열 권한 부여, 워크로드 그룹 권한 부여, 행 정책이 되어 사용자의 모든 신원에 부여됩니다. 데이터베이스나 카탈로그 전체 부여는 그로 인해 Doris가 더 많은 권한을 주지 않을 때만 합니다. [Apache Doris 에이전트](/ko/external/doris-agent/)를 참고하십시오.
- 접근 기록은 Doris의 감사 로그 테이블에서 가져옵니다. 통합 테스트는 Doris 2.1, 3.1, 4.0, 4.1을 다룹니다.

## MongoDB

- MongoDB 서비스 플러그인: 데이터베이스와 컬렉션. 복제본 세트나 샤딩 클러스터에 연결하고 SCRAM, 클라이언트 인증서, LDAP 또는 Kerberos로 로그인합니다. [MongoDB](/ko/plugins/mongodb/)를 참고하십시오.
- 배포 옆에서 실행되는 에이전트: 사용자마다 MongoDB 역할 하나를 유지하고 그 권한을 한 번에 교체합니다. MongoDB가 알려 주는 상속된 권한으로 GrantForge 밖의 기본 제공 역할과 사용자 정의 역할이 실제로 무엇을 주는지 보고합니다. [MongoDB 에이전트](/ko/external/mongodb-agent/)를 참고하십시오.
- 접근 기록은 Enterprise나 Percona의 감사 로그 파일 또는 프로파일러에서 가져옵니다. 통합 테스트는 MongoDB 6.0, 7.0, 8.0, 9.0을 다루며, Kerberos는 Percona Server for MongoDB에서 검증했습니다.

## Redis와 Valkey

- Redis 서비스 플러그인: 키, 채널, 노드. 단독 서버와 그 복제본 또는 클러스터에 연결하고 ACL 사용자로 로그인하며, TLS도 선택할 수 있습니다. [Redis](/ko/plugins/redis/)를 참고하십시오.
- 배포 옆에서 실행되는 에이전트: 모든 노드에서 각 사용자의 ACL 선택자를 정책과 일치시키고 명령 하나로 통째로 교체합니다. 루트 권한은 계속 운영자가 관리하며, 에이전트는 그 권한이 정책이 거부하는 접근을 허용하는지 `ACL DRYRUN`으로 Redis에 묻습니다. [Redis 에이전트](/ko/external/redis-agent/)를 참고하십시오.
- 거부 기록은 각 노드의 ACL 로그에서 가져옵니다. 통합 테스트는 Redis 7.2, 7.4, 8.2, 8.10과 Valkey 8.1, 9.1, 그리고 Redis 8.10 클러스터를 다룹니다.

## 에이전트

- ClickHouse, PostgreSQL, OpenSearch 에이전트와 이번 릴리스에 추가된 시스템 옆 에이전트는 새 `grantforge-agent-sync` 코어를 공유합니다. 시작 프로그램, 설정, 타이머, 동기화 흐름, 감사 읽기 위치, 로그 파일 추적이 여기에 있습니다. 각 에이전트는 자기 시스템 고유의 부분만 갖고 있으며 설정과 로그 형식은 바뀌지 않았습니다.

## 신원과 조직

- 데이터 소스: 조직 구조 동기화는 신원 소스와 따로 구성하며, 첫 어댑터는 공식 서버 SDK를 사용하는 DingTalk입니다. SSO로 로그인한 사용자는 신뢰할 수 있는 이메일로 부서와 주 부서에 자동 연결됩니다. 그 테이블은 지원하는 여섯 데이터베이스 모두에서, SQL Server와 Oracle을 포함해 마이그레이션됩니다. [신원 소스(LDAP와 OIDC)](/ko/guide/identity-sources/)를 참고하십시오.
- OpenID Connect 신원 소스는 휴대폰 번호와 아바타를 동기화할 수 있고, 인가 요청에 매개변수(예: Casdoor의 `provider_hint`)를 추가할 수 있습니다. 프로토콜 자체의 매개변수는 덮어쓸 수 없습니다.

## 인가와 리소스 카탈로그

- 사용자 직접 권한 부여: 업무 애플리케이션의 메뉴, 페이지, 버튼 또는 API를 한 사용자에게만 허용하며 만료 시간을 지정할 수 있습니다. 역할 권한과 함께 계산되며 역할의 거부가 여전히 우선합니다. [사용자](/ko/guide/users/)를 참고하십시오.
- 리소스 카탈로그는 애플리케이션의 리소스 트리를 JSON으로 내보내 다른 애플리케이션으로 가져올 수 있습니다. 가져오기는 먼저 사전 검사를 거치며 충돌하면 아무것도 적용되지 않습니다. 플랫폼 관리자는 조건에 맞는 애플리케이션 트리를 비울 수 있습니다. [리소스 카탈로그와 API 카탈로그](/ko/guide/catalog/)를 참고하십시오.

## 서버

- 시작할 때 Spring Boot 배너 대신 GrantForge 배너와 버전, Java 버전을 출력합니다.

## 문서와 릴리스

- 플러그인 탭은 개요로 시작하고 시스템을 종류별로 접을 수 있는 사이드바에 묶으며, 각 시스템의 적용 방식, 행 필터와 마스킹 지원, 검증된 버전을 보여 줍니다. 각 README도 같은 순서로 구성 요소를 나열합니다.
- CI는 모든 페이지가 모든 언어로 완전히 번역되었는지 검사합니다. 문단, 제목, 표, 코드 블록, 링크가 중국어 페이지와 같아야 하고, 다른 언어의 문자가 없어야 하며, 영어 페이지에서 그대로 옮긴 문장도 없어야 합니다. README 11개도 영어 README를 기준으로 같은 검사를 받습니다. 이 검사로 찾은 누락된 번역은 모두 채웠습니다.
- 버전 검사가 모든 README의 버전 배지를 최신으로 유지합니다.
- 문서 게시와 릴리스 워크플로는 더 이상 포크에서 실행되지 않습니다.
- 서버 `grantforge-server`는 더 이상 Maven 저장소에 배포하지 않습니다. 모든 플러그인을 묶어 저장소의 크기 제한을 넘기 때문이며, 서버는 릴리스 아카이브와 이미지로 제공됩니다.

## 수정 사항

- 리소스 편집 창에서 리소스 유형을 바꾸면 더 이상 맞지 않는 리소스 코드를 지웁니다.
- JavaScript 연동 가이드의 마지막 코드 블록이 뒤따르는 본문을 삼키지 않으며, Docker와 빠른 시작 페이지의 콘솔 주소가 뒤의 글자까지 링크로 만들지 않습니다.
- 보안 권고를 해결한 버전으로 의존성을 업그레이드했습니다: MariaDB Connector/J 3.5.11, OpenTelemetry 1.67.0, Guava 33.7.2, Snappy 1.1.10.9, 그리고 콘솔과 SDK의 vue-i18n, glob, minimatch.
