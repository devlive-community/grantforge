필드 권한은 역할의 보유자가 각 제어 필드를 어떻게 **보고 수정**할 수 있는지 결정합니다. 역할 행에서 **필드 권한**을 클릭해 설정합니다.

![필드 권한](/screenshots/role-fields.png)

## 보기 방식

| 방식 | 효과 |
| --- | --- |
| 표시 | 원본 값을 표시 |
| 마스킹 | 마스킹 방식에 따라 값을 일부 숨김: 이메일(첫 글자와 도메인 유지), 휴대폰 번호(138\*\*\*5678), 신분증 번호(앞 6자리와 뒤 4자리 유지), 앞뒤 문자 유지, 전체 숨김 |
| 숨김 | 이 필드를 전혀 반환하지 않으며, 목록에서 해당 열을 표시하지 않음 |

## 수정 방식

| 방식 | 효과 |
| --- | --- |
| 수정 가능 | 입력하고 수정할 수 있음 |
| 읽기 전용 | 폼에서 비활성화됨. API를 직접 호출해 수정하면 어느 필드인지 지목한 오류가 반환됨 |

## 병합 규칙

- 설정되지 않은 필드는 보유자의 다른 역할이 결정합니다. 어떤 역할에서도 설정하지 않으면 필드는 표시되고 수정 가능합니다.
- 여러 역할이 같은 필드를 설정하면 **가장 관대한** 설정이 적용됩니다(표시 > 마스킹 > 숨김, 수정 가능 > 읽기 전용).
- 검색과 내보내기도 필드 권한을 준수합니다. 숨김 필드는 검색에 사용할 수 없고, 내보낼 때는 규칙에 따라 숨기거나 마스킹합니다.

## 제어 필드

제어 필드는 서버 측 코드에서 선언합니다(현재는 사용자의 이메일과 최근 로그인 시각). **플랫폼 관리 → 리소스 카탈로그**에서 해당 필드가 어떤 인터페이스에 나타나는지 확인할 수 있습니다. 비즈니스 애플리케이션의 필드 제어는 애플리케이션이 직접 구현할 수 있으며, 규칙은 마찬가지로 Open API에서 가져옵니다.
