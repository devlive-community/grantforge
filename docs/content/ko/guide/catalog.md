## 리소스 카탈로그

**플랫폼 관리 → 리소스 카탈로그**는 각 애플리케이션의 리소스 트리를 관리합니다. 콘솔 자체(`grantforge-console`)는 내장 애플리케이션이며, 그 페이지, 버튼과 API는 시작할 때 자동 등록되고 삭제할 수 없습니다.

![리소스 카탈로그](/screenshots/resources.png)

- **애플리케이션**: 비즈니스 애플리케이션을 생성, 수정, 삭제합니다. 클라이언트나 리소스가 있는 애플리케이션은 삭제할 수 없습니다.
- **리소스**: 모듈, 메뉴, 페이지, 탭, 버튼, API, 데이터 엔티티, 필드입니다. 타입이 리소스를 어디에 놓을 수 있는지 결정합니다. 버튼은 페이지나 탭 아래에만, 필드는 데이터 엔티티 아래에만 놓일 수 있습니다. 리소스는 끌어서 위치를 조정할 수 있으며, 최대 15단계까지입니다.
- **상태**: 리소스를 숨기거나 비활성화할 수 있습니다. 권한이 없을 때 버튼을 "숨김"으로 할지 "비활성화"로 할지 선택할 수 있습니다.
- **의존 관계**: 버튼은 자신이 호출하는 API를, 페이지는 데이터를 불러오는 API를 "필요"로 합니다. 권한을 부여할 때 이런 의존 관계가 함께 도출되며, 상세 페이지는 의존 관계를 그래프로 보여줍니다.
- **OAuth 클라이언트**: 비즈니스 애플리케이션용 클라이언트를 등록합니다. [OAuth 2.1과 OpenID Connect](/ko/integration/oauth/)를 참고하세요.
- **필드**: 필드를 선택하면 그 필드가 어떤 인터페이스에 나타나는지(반환하거나 수신하는지)를 보여줍니다.

## API 카탈로그

**플랫폼 관리 → API 카탈로그**는 서버가 시작할 때 자동 등록된 모든 인터페이스와 각각의 접근 요구 사항을 나열합니다. 공개, 로그인만 하면 사용 가능, 또는 특정 권한 코드 필요 중 하나입니다. 권한이 필요한 인터페이스는 권한 코드별로 리소스 카탈로그에 분류되며, 역할에 권한을 부여할 때 이 권한을 참조합니다. 인터페이스가 추가되거나 폐기되거나 권한 코드가 바뀌면 "확인 대기 중인 변경"으로 표시되며, 확인하면 카탈로그가 업데이트됩니다.

![API 카탈로그](/screenshots/apis.png)

## 카탈로그 건강 검사

**플랫폼 관리 → 카탈로그 건강 검사**는 조용히 망가진 설정을 찾습니다. 효력을 내지 못하는 권한 부여, 동작할 수 없는 버튼(필요한 API 누락), 아무도 호출할 수 없는 API, 끊어진 의존 관계가 대상입니다. 건강 검사는 데이터를 읽기만 하며 어떤 것도 수정하지 않습니다.

![카탈로그 건강 검사](/screenshots/health.png)
