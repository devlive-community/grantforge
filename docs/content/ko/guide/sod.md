**접근 제어 → 직무 분리**는 한 사람이 동시에 가져서는 안 되는 역할(예: 결제와 승인)을 설정하고, 현재 제약을 위반하는 계정을 보여줍니다.

![직무 분리](/screenshots/sod.png)

## 제약

| 설정 | 설명 |
| --- | --- |
| 상호 배타적인 역할 | 역할 2–50개 |
| 계정당 최대 보유 수 | 기본값 1이며, "세 개 중 두 개까지"처럼 설정할 수 있습니다 |
| 모드 | **강제**: 충돌을 일으키는 역할 할당과 상속을 거부합니다. **보고만**: 변경은 허용하고 충돌 목록에만 표시합니다 |
| 활성화 | 비활성화된 제약은 거부하지도 보고하지도 않습니다 |

"보유"는 모든 경로를 포함합니다. 직접 할당, 사용자 그룹이나 부서, 직위를 통해 얻는 경우, 그리고 역할 상속을 통해 얻는 경우가 해당됩니다. 유효 기간이 아닌 할당과 비활성화된 역할은 계산하지 않습니다.

## 강제 적용 시점

강제 모드에서는 다음 변경이 저장되기 전에 그것이 영향을 주는 모든 계정을 검사합니다.

- 역할을 할당하거나, 할당의 유효 기간이나 "하위 부서 포함" 여부를 수정하는 경우;
- 역할의 상속 관계를 수정하는 경우;
- 권한 요청을 승인하는 경우([권한 요청과 승인](/ko/guide/access-requests/) 참고).

**이번 변경으로 새로 생긴** 충돌만 거부하며, 누가, 어떤 역할로, 어떤 제약을 위반했는지 알려줍니다. 제약이 적용되기 전부터 있던 충돌은 다른 관련 없는 변경을 막지 않습니다. 그 충돌은 계속 충돌 목록에 표시되며, 사람이 직접 처리해야 합니다.

> [!WARNING]
> 사람을 사용자 그룹, 부서 또는 직위에 추가할 때는 이 검사를 하지 않습니다. 이런 경로로 생긴 충돌은 충돌 목록에 나타나므로, 정기적으로 확인하세요.

## 충돌 목록

오른쪽에는 활성화된 제약을 위반하는 모든 계정이 모드와 관계없이 표시됩니다. 계정, 제약, 보유한 역할과 허용된 상한을 보여줍니다.
