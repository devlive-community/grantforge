2026.2.0 amplía los permisos de los sistemas externos de 2026.1.0 a Apache Hive, Apache Kafka, Apache HBase, Trino y Apache Hadoop YARN, con agentes que los aplican. La lista completa de cambios está en la [comparación en GitHub](https://github.com/devlive-community/grantforge/compare/v2026.1.0...v2026.2.0).

## Apache Hive

- Un plugin de servicio de Hive: bases de datos, tablas, columnas, UDF, URL, el servicio HiveServer2 y la replicación, con los tipos de acceso de Hive tal como los define Apache Ranger; véase [Apache Hive](/es/plugins/hive/).
- Un agente de HiveServer2 que verifica cada sentencia, filtra los resultados de `SHOW`, enmascara columnas y filtra filas; véase el [agente de Hive](/es/external/hive-agent/).
- Las UDF temporales se conceden en el ámbito global solo a `tempudfadmin`, como hace Apache Ranger, porque ejecutan código elegido por el usuario.

## Apache Kafka

- Un plugin de servicio de Kafka: temas, grupos, identificadores transaccionales, el clúster, tokens de delegación y usuarios SCRAM, con los tipos de acceso e implicaciones propios de Kafka; véase [Apache Kafka](/es/plugins/kafka/).
- Un autorizador de brokers y controladores que verifica cada solicitud; véase el [agente de Kafka](/es/external/kafka-agent/).

## Apache HBase

- Un plugin de servicio de HBase: espacios de nombres, tablas, familias de columnas y columnas, además del ámbito global para operaciones sobre todo el clúster; véase [Apache HBase](/es/plugins/hbase/).
- Un coprocesador para el master y los region servers que verifica las operaciones, devuelve solo las columnas que un usuario puede leer y oculta lo que no puede ver; véase el [agente de HBase](/es/external/hbase-agent/).

## Trino

- Un plugin de servicio de Trino: catálogos, esquemas, tablas, columnas, funciones, procedimientos y propiedades de sesión; véase [Trino](/es/plugins/trino/).
- Dos controles de acceso del sistema, uno para Trino 470 a 478 y otro para Trino 479 y posteriores, que verifican las consultas, filtran filas y enmascaran columnas; véanse los [agentes de Trino](/es/external/trino-agent/).

## Apache Hadoop YARN

- Un plugin de servicio de YARN: colas y aplicaciones, con los tipos de acceso `submit_app` y `admin_queue` de YARN; véase [Apache Hadoop YARN](/es/plugins/yarn/).
- Un proveedor de autorización en el ResourceManager que decide el envío, las colas y la administración del clúster según la política, con condiciones sobre las direcciones de los clientes; véase el [agente de YARN](/es/external/yarn-agent/).

## Motor de políticas y agentes

- Las políticas deciden el acceso a lo que hay por debajo de un recurso: listar una base de datos cuenta las políticas de tablas del usuario, y el nuevo tipo de acceso `_any` se permite cuando se permite algún acceso sobre el recurso o por debajo de él.
- Las políticas responden si un usuario puede hacer algo con algún recurso de un nivel, como Kafka pregunta antes de que los productores idempotentes escriban.
- Los agentes agrupan los accesos permitidos idénticos de una ventana de tiempo en un único evento de auditoría con un contador y el momento del último; los rechazos se registran de inmediato.
- Los agentes pueden mostrar sus políticas de acceso en los términos del propio sistema.
- La API de plugins 1.2.0 proporciona los realms de Kerberos una sola vez a todos los plugins, que ya no sobrescriben mutuamente su `krb5.conf`.

## Documentación y publicación

- Los plugins y agentes de YARN, Hive, Kafka, HBase y Trino están documentados en los once idiomas.
- El README enumera los componentes compatibles y las versiones que verifican las pruebas de integración.
- Las etiquetas de versión ejecutan la CI completa y la publicación espera a esa ejecución; la distribución se compila en paralelo; npm publica mediante publicación de confianza (trusted publishing).
- Las versiones sin registro de publicación se rechazan al etiquetar; la CI ejecuta, tras una puerta Java común, solo los trabajos que necesita un cambio.

## Correcciones

- Los índices de PostgreSQL se preparan después de cargar los datos, de modo que las llamadas a la API cronometradas se ejecuten sobre tablas analizadas.
- Las pruebas de los jar del agente de ZooKeeper se ejecutan después del empaquetado.
- Los despliegues de Maven omiten las pruebas de integración; un tiempo de espera de la JVM bifurcada en el agente de HDFS 3.2 había hecho fallar el despliegue en GitHub Packages.
- El paquete npm declara su repositorio, para que npm pueda verificar la procedencia.
