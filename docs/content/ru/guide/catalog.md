## Каталог ресурсов

**Управление платформой → Каталог ресурсов** ведёт дерево ресурсов каждого приложения. Сама консоль (`grantforge-console`) — встроенное приложение; его страницы, кнопки и API регистрируются автоматически при запуске и не могут быть удалены.

![Каталог ресурсов](/screenshots/resources.png)

- **Приложения**: создание, редактирование и удаление бизнес-приложений; приложение, у которого есть клиенты или ресурсы, удалить нельзя.
- **Ресурсы**: модули, меню, страницы, вкладки, кнопки, API, сущности данных и поля. Тип определяет, куда можно разместить ресурс: кнопки — только под страницами или вкладками, поля — только под сущностями данных. Ресурсы можно перетаскиванием переставлять, вплоть до глубины 15 уровней.
- **Статус**: ресурсы можно скрывать или отключать; при отсутствии прав можно выбрать, будут ли кнопки «скрыты» или «отключены».
- **Зависимости**: кнопка «требует» API, которые она вызывает, а страница — API, из которых загружает данные; выдачи выводят эти зависимости автоматически, а на странице сведений зависимости показаны в виде графа.
- **OAuth-клиенты**: регистрация клиентов для бизнес-приложений, см. [OAuth 2.1 и OpenID Connect](/ru/integration/oauth/).
- **Поля**: при выборе поля показывается, в каких API оно встречается (возвращается или принимается).

## Каталог API

**Управление платформой → Каталог API** перечисляет каждый API, зарегистрированный автоматически при запуске сервера, вместе с требованием к доступу: публичный, любой вошедший пользователь или конкретный код права. API, требующие авторизации, раскладываются по каталогу ресурсов по коду права, а выдачи ролей ссылаются на эти права. Если API добавлен, выведен из эксплуатации или изменился его код права, он попадает в список «ожидающих изменений»; каталог обновляется после подтверждения.

![Каталог API](/screenshots/apis.png)

## Проверка состояния каталога

**Управление платформой → Проверка состояния каталога** находит конфигурации, которые незаметно сломались: выдачи, которые больше не действуют, неработающие кнопки (нет требуемых API), API, которые никто не может вызвать, и разорванные зависимости. Проверка только читает данные и ничего не меняет.
