2026.2.0 étend les permissions des systèmes externes de 2026.1.0 à Apache Hive, Apache Kafka, Apache HBase, Trino et Apache Hadoop YARN, avec des agents qui les appliquent. La liste complète des changements se trouve dans la [comparaison GitHub](https://github.com/devlive-community/grantforge/compare/v2026.1.0...v2026.2.0).

## Apache Hive

- Un plug-in de service Hive : bases de données, tables, colonnes, UDF, URL, le service HiveServer2 et la réplication, avec les types d'accès Hive tels que définis par Apache Ranger ; voir [Apache Hive](/fr/plugins/hive/).
- Un agent HiveServer2 qui vérifie chaque instruction, filtre les résultats de `SHOW`, masque les colonnes et filtre les lignes ; voir l'[agent Hive](/fr/external/hive-agent/).
- Les UDF temporaires sont accordées au niveau global uniquement à `tempudfadmin`, comme le fait Apache Ranger, car elles exécutent du code choisi par l'utilisateur.

## Apache Kafka

- Un plug-in de service Kafka : sujets, groupes, identifiants de transaction, le cluster, les jetons de délégation et les utilisateurs SCRAM, avec les types d'accès et implications propres à Kafka ; voir [Apache Kafka](/fr/plugins/kafka/).
- Un autorisateur de broker et de contrôleur qui vérifie chaque requête ; voir l'[agent Kafka](/fr/external/kafka-agent/).

## Apache HBase

- Un plug-in de service HBase : espaces de noms, tables, familles de colonnes et colonnes, ainsi que le niveau global pour les opérations sur tout le cluster ; voir [Apache HBase](/fr/plugins/hbase/).
- Un coprocesseur pour le master et les region servers qui vérifie les opérations, ne renvoie que les colonnes qu'un utilisateur peut lire et masque ce qu'il ne peut pas voir ; voir l'[agent HBase](/fr/external/hbase-agent/).

## Trino

- Un plug-in de service Trino : catalogues, schémas, tables, colonnes, fonctions, procédures et propriétés de session ; voir [Trino](/fr/plugins/trino/).
- Deux contrôles d'accès système, l'un pour Trino 470 à 478 et l'autre pour Trino 479 et ultérieur, qui vérifient les requêtes, filtrent les lignes et masquent les colonnes ; voir les [agents Trino](/fr/external/trino-agent/).

## Apache Hadoop YARN

- Un plug-in de service YARN : files d'attente et applications, avec les types d'accès `submit_app` et `admin_queue` de YARN ; voir [Apache Hadoop YARN](/fr/plugins/yarn/).
- Un fournisseur d'autorisation dans le ResourceManager qui décide de la soumission, de la file d'attente et de l'administration du cluster selon la politique, avec des conditions sur les adresses des clients ; voir l'[agent YARN](/fr/external/yarn-agent/).

## Moteur de politiques et agents

- Les politiques décident des accès sous une ressource : lister une base de données compte les politiques de tables de l'utilisateur, et le nouveau type d'accès `_any` est autorisé lorsqu'un accès sur la ressource ou en dessous est autorisé.
- Les politiques répondent à la question de savoir si un utilisateur peut faire quelque chose avec une ressource d'un niveau, comme Kafka le demande avant les écritures des producteurs idempotents.
- Les agents regroupent les accès autorisés identiques d'une fenêtre temporelle en un événement d'audit avec un compteur et l'instant du dernier ; les refus sont enregistrés immédiatement.
- Les agents peuvent afficher leurs politiques d'accès dans les termes du système lui-même.
- L'API de plug-in 1.2.0 fournit les domaines Kerberos une seule fois à tous les plug-ins, qui n'écrasent plus mutuellement leur `krb5.conf`.

## Documentation et publication

- Les plug-ins et agents YARN, Hive, Kafka, HBase et Trino sont documentés dans les onze langues.
- Le README liste les composants pris en charge et les versions vérifiées par les tests d'intégration.
- Les tags de version exécutent la CI complète et la publication attend cette exécution ; le paquet de distribution est construit en parallèle ; npm publie via la publication de confiance (trusted publishing).
- Les versions sans journal de publication sont refusées au moment du tag ; la CI n'exécute, après une porte Java commune, que les tâches dont un changement a besoin.

## Corrections

- Les index PostgreSQL sont préparés après le remplissage, de sorte que les appels d'API chronométrés s'exécutent sur des tables analysées.
- Les tests des jars de l'agent ZooKeeper s'exécutent après l'empaquetage.
- Les déploiements Maven ignorent les tests d'intégration ; un dépassement de délai de la JVM forkée sur l'agent HDFS 3.2 avait fait échouer le déploiement GitHub Packages.
- Le paquet npm déclare son dépôt, afin que npm puisse vérifier la provenance.
