2026.2.0 étend les permissions des systèmes externes de 2026.1.0 à Apache Hive, Apache Kafka, Apache HBase, Trino et Apache Hadoop YARN. Chaque système dispose d'un plug-in de service et d'un agent qui applique ses politiques. La liste complète des modifications figure dans la [comparaison GitHub](https://github.com/devlive-community/grantforge/compare/v2026.1.0...v2026.2.0).

## Apache Hive

- Plug-in de service Hive : recherche de bases de données, tables, colonnes et UDF, connexion par mot de passe ou Kerberos ; voir [Apache Hive](/fr/plugins/hive/).
- Agent HiveServer2 : autorise chaque instruction, filtre les résultats de `SHOW`, masque les colonnes et filtre les lignes ; voir [Agent Hive](/fr/external/hive-agent/).
- Les UDF temporaires ne sont accordées au niveau global qu'à `tempudfadmin`, comme dans Apache Ranger, car elles exécutent du code choisi par l'utilisateur.

## Apache Kafka

- Plug-in de service Kafka : recherche de sujets, groupes de consommateurs, identifiants transactionnels et utilisateurs, connexion par PLAIN, SCRAM ou Kerberos, en clair ou en TLS ; voir [Apache Kafka](/fr/plugins/kafka/).
- Autorisateur pour les brokers et contrôleurs : vérifie chaque requête, affiche les politiques sous forme d'ACL en lecture seule et regroupe les accès répétés en un seul événement d'audit ; voir [Agent Kafka](/fr/external/kafka-agent/).

## Apache HBase

- Plug-in de service HBase : recherche d'espaces de noms, tables et familles de colonnes, via ZooKeeper ou des serveurs d'amorçage, en simple ou avec Kerberos ; voir [Apache HBase](/fr/plugins/hbase/).
- Coprocesseur pour les masters et les region servers : vérifie les opérations, lectures et écritures à chaque niveau, ne renvoie que les colonnes lisibles et masque ce qu'un utilisateur ne peut pas utiliser ; voir [Agent HBase](/fr/external/hbase-agent/).

## Trino

- Plug-in de service Trino : recherche de catalogues, schémas, tables, colonnes et propriétés de session, connexion par mot de passe, jeton JSON Web ou Kerberos sur TLS ; voir [Trino](/fr/plugins/trino/).
- Deux contrôles d'accès système : l'un pour Trino 470 à 478, l'autre pour 479 et les versions ultérieures. Ils vérifient les requêtes, ne listent que ce qu'un utilisateur peut utiliser, filtrent les lignes et masquent les colonnes ; le second vérifie en plus les branches de tables et les rafraîchissements de vues ; voir [Agent Trino](/fr/external/trino-agent/).

## Apache Hadoop YARN

- Plug-in de service YARN : connexion à un ResourceManager ou à une paire haute disponibilité, en simple ou avec Kerberos, recherche de files et de noms d'applications ; voir [Apache Hadoop YARN](/fr/plugins/yarn/).
- Fournisseur d'autorisation dans les ResourceManagers : décide par politique des soumissions, des files et de l'administration du cluster, avec des conditions sur les adresses clientes ; voir [Agent YARN](/fr/external/yarn-agent/).

## Moteur de politiques et agents

- Les politiques décident de l'accès à toute ressource d'un niveau et à ce qui se trouve sous une ressource ; lister une base de données tient ainsi compte des politiques de tables de l'utilisateur.
- Les agents qui vérifient chaque requête regroupent les accès identiques autorisés d'une fenêtre temporelle en un événement d'audit avec un compteur et l'heure du dernier ; les refus sont enregistrés immédiatement.
- Les agents peuvent afficher leurs politiques d'accès dans les termes propres au système.

## Documentation et publication

- La documentation des plug-ins et agents YARN, Hive, Kafka, HBase et Trino est disponible dans les onze langues.
- Le README liste les composants pris en charge et les versions vérifiées par les tests d'intégration.
- La CI n'exécute, après une porte Java commune, que les tâches nécessaires à un changement, et refuse une étiquette sans journal de publication.

## Corrections

- Les index PostgreSQL sont préparés après l'insertion des données, afin que les appels d'API chronométrés s'exécutent sur des tables analysées.
- Les tests du jar de l'agent ZooKeeper s'exécutent après l'empaquetage.
