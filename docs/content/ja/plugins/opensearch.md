OpenSearch プラグインは、インデックス、データストリーム、フィールド、クラスターを検索し、OpenSearch 自身の考え方でアクセスポリシーを管理します。フィールドの読み取り、インデックスへの書き込み・削除・作成・管理、クラスター自身の操作に加え、フィールドのマスクとインデックスの行フィルターにも対応します。プラグイン ID とサービスタイプはどちらも `opensearch` です。サービスプラグインは GrantForge サーバーで動き、クラスターの隣で動く [OpenSearch エージェント](/ja/external/opensearch-agent/) がセキュリティプラグイン自身のロール、フィールドレベルセキュリティ、マスクフィールド、ドキュメントレベルセキュリティでポリシーを適用します。

リポジトリの Testcontainers 統合テストは、セキュリティプラグインを備えた OpenSearch `2.19`、`3.3`、`3.6`、`3.9` を対象としています。これは他のすべてのバージョンを認定するものではありません。

## インストール

配布物の `plugins/opensearch` にこのプラグインが含まれています。**プラットフォーム管理 → プラグイン** で `opensearch` が有効になっていることを確認し、プラグインディレクトリを更新したら再スキャンしてください。プラグインは独自のクラスローダーの中で、OpenSearch 自身の低レベル REST クライアントを使ってノードと通信します。

## データサービスの追加

1. **データ権限 → データサービス** を開き、サービスを追加して OpenSearch（`opensearch`）を選びます。
2. 1 つまたは複数のノードを URL で入力します。
3. 検索ユーザーのサインイン方法を選び、資格情報を入力して接続をテストし、サービスを保存します。テストはサインインしてクラスターを説明します。OpenSearch のバージョンとクラスター名、サインインしたユーザー、インデックスとデータストリームの数です。セキュリティプラグインのないクラスターはテストに失敗します。エージェントはそれを通じてポリシーを適用するためです。

検索ユーザーは GrantForge がリソースを見つけるためのもので、読み書きするユーザーとは別です。接続テストが成功しても、アクセスがすでにポリシーに従っているわけではありません。

| 設定 | 用途 |
| --- | --- |
| `opensearch.hosts` | 必須：URL 形式のノード。例：`https://opensearch1.example.com:9200`。複数はカンマ区切りで、接続できないときは順に試します。スキームがなければ `https`、ポートの既定は `9200` で、1 つのサービスのノードはすべて `http` かすべて `https` です |
| `authentication` | `password`（既定）または `certificate`：セキュリティプラグインがユーザーに対応付ける TLS クライアント証明書 |
| `username`、`password` | password：検索ユーザーとそのパスワード。パスワードは暗号化して保存 |
| `ssl.verificationMode` | OpenSearch Dashboards と同じ名前：`full`（既定）はノードの証明書と名前を、`certificate` は証明書だけを確認し、`none` は何も確認しません |
| `ssl.certificateAuthorities` | ノードを検証する **GrantForge サーバー** 上の PEM CA 証明書のパス。空なら JVM のものを使います |
| `ssl.certificate`、`ssl.key` | certificate：GrantForge サーバー上の PEM クライアント証明書とその秘密鍵のパス。鍵は PKCS #8 または旧来の OpenSSL 形式。`https` のノードが必要です |
| `ssl.keyPassphrase` | certificate：暗号化された秘密鍵のパスフレーズ。暗号化して保存 |
| `timeout` | 接続とリクエストにかけてよい時間。既定 `30000`、範囲 `1..600000` ミリ秒 |

あるサインイン方法の設定は別の方法では拒否されるため、サービスはどうサインインするかを明確にします。拒否されたサインイン、足りない権限、接続できないノード、検証できない証明書は、そのとおりに報告されます。

### 検索ユーザーに見えるもの

検索ユーザーは一覧にするものを読める必要があります。インデックスとデータストリームは OpenSearch の resolve API、フィールドはフィールド機能（field capabilities）、クラスター名はクラスターの説明から得ます。組み込みの `readall` ロールが前の 2 つを与えます。`cluster:monitor/main` のないユーザーも接続テストには合格し、その場合テストはバージョンを示しません。名前がドットで始まるインデックスとデータストリーム、つまり隠しインデックスとシステムインデックスは、入力がドットで始まるときだけ一覧に出ます。データストリームのバッキングインデックスはそのデータストリームとして一覧に出ます。フィールドはドキュメントのフィールドです。OpenSearch 自身のメタデータフィールド、オブジェクト、`name.keyword` のようにフィールドをもう一度索引するマルチフィールドは除外されます。フィールドレベルセキュリティはそれらを元のフィールドとともに表示または隠すためです。

## リソースとアクセスタイプ

| レベル | 照合 | アクセスタイプ |
| --- | --- | --- |
| `index` | ワイルドカード、大文字小文字を区別。インデックスまたはデータストリームの名前 | `index`、`delete`、`create_index`、`manage_aliases`、`monitor`、`manage` |
| `field` | ワイルドカード、大文字小文字を区別。インデックスの下、`address.city` のようなフィールドのパス | `read` |
| `cluster` | ワイルドカード、大文字小文字を区別。クラスターの名前 | `cluster_monitor`、`manage_snapshots`、`manage_templates`、`manage_pipelines` |

| アクセスタイプ | セキュリティプラグインのアクショングループ |
| --- | --- |
| `read` | `read`：検索、取得、カウントなど |
| `index` | `index`：ドキュメントの索引付けと更新。bulk も含む |
| `delete` | `delete`：ドキュメントの削除 |
| `create_index` | `create_index`：インデックスの作成。最初の書き込みで作られる場合も含む |
| `manage_aliases`、`monitor` | `manage_aliases`、`indices_monitor` |
| `manage` | `manage`：インデックスの削除を含むすべての管理操作。`create_index`、`manage_aliases`、`monitor` を含みます |
| `cluster_monitor`、`manage_snapshots` | `cluster_monitor`、`manage_snapshots` |
| `manage_templates`、`manage_pipelines` | `cluster_manage_index_templates`、`cluster_manage_pipelines` |

読み取りは、フィールドレベルセキュリティがドキュメントのフィールドを表示するとおりにフィールドごとに決まります。`read` のポリシーはフィールドを指定し、`*` はすべてのフィールドです。そのため、ポリシーはインデックスを許可しつつその中の 1 フィールドを拒否でき、ユーザーは残りのすべてのフィールドを読めます。ポリシーの値では、`*` は任意の文字列に、`?` は 1 文字に一致します。ポリシーエディターは、インデックスとデータストリーム、ポリシーが指すインデックスのフィールド、クラスターを候補として示します。

ポリシーが許可するものを使うには、OpenSearch ではさらに権限が要ります。読み取りにはマルチ検索、マルチ取得、スクロールが、書き込みには bulk が必要です。これらは独立したアクセスタイプではなく、エージェントがクラスターの複合操作と一緒に付与します。

### マスク

フィールドのマスクポリシーは、セキュリティプラグインのマスクフィールドと同じく、ドキュメントでも集計でもユーザーに値をマスクして見せます。

| マスク | ユーザーに見えるもの |
| --- | --- |
| 伏せ字（Redact） | 大文字は `X`、小文字は `x`、数字は `n` |
| 部分マスク：末尾 4 文字 / 先頭 4 文字を表示 | それ以外の各文字を `x` |
| ハッシュ（SHA-256） | 値の SHA-256 ハッシュ |
| クラスターのソルト付きハッシュ（BLAKE2b） | クラスターのソルトを鍵とするセキュリティプラグイン自身のハッシュ。等しい値は等しいままですが、元の値は引けません |
| カスタム | `SHA-512` のようなハッシュアルゴリズム、または `/[0-9]/::*` のような正規表現とその置換 |
| マスクなし | 値そのもの |

### 行フィルター

インデックスの行フィルターポリシーは、クエリに一致するドキュメントだけをユーザーに見せます。クエリはドキュメントレベルセキュリティが受け取る OpenSearch のクエリ DSL で、例えば `{"term": {"region": "EU"}}` です。`${user.name}` のようなセキュリティプラグインの置換も使えます。他のサービスと同様に、ユーザーには自分に適用される最初のポリシーのフィルターが適用されます。行フィルターが確かめられるのはユーザーが読めるフィールドだけです。フィールドレベルセキュリティはクエリからも他のフィールドを隠します。

## ポリシーの例

クラスターにインデックス `logs-2026.10.26` と `hr` があるとします。同じデータサービスに、次の有効なポリシーを作成します。

| リソース | ルール |
| --- | --- |
| `index=logs-*`、`field=*` | グループ `analysts` に `read` を許可 |
| `index=logs-*`、`field=client_ip` | グループ `analysts` に `read` を拒否 |
| `index=logs-*` | ユーザー `logstash` に `index` と `create_index` を許可 |
| `index=hr`、`field=*` | グループ `hr` に `read` を許可 |
| `index=hr`、`field=salary`（マスク） | グループ `hr` にクラスターのソルト付きハッシュを表示 |
| `index=hr`（行フィルター） | ユーザー `emea-hr` に `{"term": {"region": "EMEA"}}` のドキュメントだけを表示 |
| `cluster=*` | グループ `ops` に `cluster_monitor` を許可 |

エージェントが新しいスナップショットを適用すると、`analysts` のメンバーはクライアントのアドレスを除くすべてのログフィールドを読め、`logstash` は明日の `logs-2026.10.27` にすぐ書き込み、最初のドキュメントでそれを作成し、`hr` のメンバーには給与がハッシュで見え、`emea-hr` はその地域の従業員だけを見て、`ops` のメンバーはクラスターの状態と統計を読めます。

## ポリシーの適用

サービスプラグインはポリシーを管理し、リソースを検索します。ポリシーを適用するには、クラスターごとに 1 つの OpenSearch エージェントが必要です。配置と確認は [OpenSearch エージェント](/ja/external/opensearch-agent/) にあります。
