Redis プラグインは、Redis と Valkey のデプロイメントのキー、チャンネル、ノードを検索し、Redis 自身の考え方でアクセスポリシーを管理します。パターンごとのキーの読み書き、チャンネルの購読と発行、各ノードの監視です。プラグイン ID とサービスタイプはどちらも `redis` です。サービスプラグインは GrantForge サーバーで動き、デプロイメントの隣で動く [Redis エージェント](/ja/external/redis-agent/) がすべてのノードで Redis 自身の ACL によってポリシーを適用します。

リポジトリの Testcontainers 統合テストは、Redis `7.2`、`7.4`、`8.2`、`8.10` と Valkey `8.1`、`9.1` のレプリカ 1 台付きプライマリ、および Redis `8.10` のクラスターを対象としています。これは他のすべてのバージョンを認定するものではありません。

## インストール

配布物の `plugins/redis` にこのプラグインが含まれています。**プラットフォーム管理 → プラグイン** で `redis` が有効になっていることを確認し、プラグインディレクトリを更新したら再スキャンしてください。プラグインは独自のクラスローダーの中で、Jedis を使って Redis と通信します。

## データサービスの追加

1. **データ権限 → データサービス** を開き、サービスを追加して Redis（`redis`）を選びます。
2. ノードを 1 つ以上入力します。クラスターの残りのノードとプライマリのレプリカは、そこから見つけます。
3. 検索ユーザーを入力して接続をテストし、サービスを保存します。テストはサインインしてデプロイメントを説明します。Redis か Valkey かとそのバージョン、単一サーバー、レプリカ付きプライマリ、クラスターのどれか、誰がサインインしたかです。

検索ユーザーは GrantForge がリソースを見つけるためのもので、読み書きをするユーザーとは別です。接続テストが成功しても、アクセスがすでにポリシーに従っているわけではありません。

| 設定 | 用途 |
| --- | --- |
| `redis.nodes` | 必須：ノードのアドレス `host:port`。例：`redis1.example.com:6379`。カンマ区切りで、順に試します。ポートを書かなければ `6379` です |
| `username` | 検索ユーザー。ACL ユーザーです。空ならデフォルトユーザーとしてサインインします |
| `password` | そのパスワード。暗号化して保存 |
| `tls.mode` | `disable`（既定）、サーバーの証明書を確認する `verify-ca`、名前も確認する `verify-full` |
| `tls.ca.file` | TLS：サーバーを検証する **GrantForge サーバー** 上の PEM CA 証明書のパス。空なら JVM のものを使います |
| `tls.certificate.file` | TLS、クライアント証明書を求めるサーバー向け：**GrantForge サーバー** 上の PEM クライアント証明書のパス。鍵を含めても構いません |
| `tls.key.file` | 証明書の PEM 鍵が別ファイルのとき、その **GrantForge サーバー** 上のパス |
| `tls.key.password` | 暗号化された鍵のパスワード。暗号化して保存 |
| `timeout` | 接続と 1 つのコマンドにかけてよい時間。既定 `10000`、範囲 `1..600000` ミリ秒 |

拒否されたサインイン、権限が足りない検索ユーザー、接続できないノードは、そのとおりに報告されます。

### 検索ユーザーに見えるもの

キーは各プライマリで `SCAN` を使って探し、キーがいくつあっても検索が速く済むよう数回までに留めます。チャンネルは今購読者がいるものです。`SCAN` はユーザーのキーパターンに関係なくすべてのキーを一覧にするため、検索ユーザーに値を読む権限は要りません。

```text
ACL SETUSER lookup on >… -@all +@connection +scan +pubsub|channels +info +cluster|nodes +acl|whoami ~* &*
```

## リソースとアクセスタイプ

| レベル | 照合 | アクセスタイプ |
| --- | --- | --- |
| `key` | ワイルドカード、大文字小文字を区別。キーまたはキーのパターン | `read`、`write` |
| `channel` | ワイルドカード、大文字小文字を区別。チャンネルまたはチャンネルのパターン | `subscribe`、`publish` |
| `node` | ワイルドカード、大文字小文字を区別しない。ノードのアドレス `host:port` | `monitor` |

| アクセスタイプ | Redis が許可すること |
| --- | --- |
| `read` | キーに対する `@read` のコマンド、つまり `%R~` |
| `write` | キーに対する `@write` のコマンド、つまり `%W~`。削除も含みます |
| `subscribe` | `SUBSCRIBE`、`PSUBSCRIBE`、`SSUBSCRIBE` をチャンネルに対して、 `&` |
| `publish` | `PUBLISH`、`SPUBLISH` をチャンネルに対して、 `&` |
| `monitor` | `INFO`、`DBSIZE`、`LATENCY LATEST`、`LATENCY HISTORY`、`MEMORY STATS` |

ポリシーの値では、`*` は任意の文字列に、`?` は 1 文字に一致し、Redis 自身のパターンと同じです。Redis はキーとチャンネルをパターンで付与し、エージェントに一覧を返せないため、ポリシーの値は、ポリシーがそのパターン全体でユーザーを同じに決める場合に限り、独立したパターンとして付与されます。ポリシーがその中で異なる決定をするパターン、たとえばポリシーが `sales:card:*` を拒否するときの `sales:*` は保留され、その旨が伝えられます。代わりに、ポリシーが同じに決めるキーやパターンを指定してください。角かっこ、バックスラッシュ、丸かっこ、空白を含む値は決して付与されません。

`FLUSHALL` や `KEYS` のように Redis が危険とみなすコマンドは決して与えず、パターンに関係なくキーを一覧にする `SCAN` と `RANDOMKEY` は、すべてのキーを読めるユーザーにだけ与えます。Redis の ACL にはデータベースがないため、パターンはノードのすべてのデータベースのキーを指します。

Redis は値の中をフィルターせず、マスクもしないため、このサービスタイプはどちらも提供しません。

## ポリシーの例

同じデータサービスに、次の有効なポリシーを作成します。

| リソース | ルール |
| --- | --- |
| `key=sales:*` | グループ `analysts` に `read` を許可 |
| `key=sales:card:*` | ユーザー `billing` に `read` と `write` を許可 |
| `key=cart:*` | ユーザー `shop` に `read` と `write` を許可 |
| `channel=orders.*` | グループ `analysts` に `subscribe` を許可；ユーザー `shop` に `publish` を許可 |
| `node=*` | ユーザー `dashboards` に `monitor` を許可 |

エージェントがスナップショットを適用すると、`analysts` のメンバーはすべての `sales:` キーを読んで注文チャンネルを購読し、`billing` は他のポリシーが中で異なる決定をしないパターンであるカードのキーを読み書きし、`shop` はカートを管理して注文イベントを発行し、`dashboards` はデータを見ずに各ノードの状態を見ます。

## ポリシーの適用

サービスプラグインはポリシーを管理し、リソースを検索します。ポリシーを適用するには、デプロイメントごとに 1 つの Redis エージェントが必要です。配置と確認は [Redis エージェント](/ja/external/redis-agent/) にあります。
