2026.4.0 は外部システム権限を Elasticsearch、Apache Doris、MongoDB、Redis と Valkey に拡張します。4 つのエージェントはいずれもシステムの横で動き、システム自身のアクセス制御をポリシーに合わせ続けます。アイデンティティと認可では、DingTalk の組織構造の同期、ユーザーへの直接付与、リソースカタログのエクスポートとインポートが加わりました。すべての変更は [GitHub の比較](https://github.com/devlive-community/grantforge/compare/v2026.3.0...v2026.4.0) を参照してください。

## Elasticsearch

- Elasticsearch サービスプラグイン：インデックスとデータストリーム、そのフィールド、クラスター。パスワード、API キー、TLS クライアント証明書でログインします。[Elasticsearch](/ja/plugins/elasticsearch/) を参照してください。
- クラスターの横で動くエージェント：ユーザーごとに Elasticsearch 自身のロールを維持し、ネイティブユーザーに割り当て、ほかの realm のユーザーにはロールマッピングで割り当てます。ライセンスが許せばフィールドレベルとドキュメントレベルのセキュリティも付けます。インデックスパターンはパターンのまま保たれ、新しいインデックスにもすぐに届きます。[Elasticsearch エージェント](/ja/external/elasticsearch-agent/) を参照してください。
- アクセスの記録は監査ログファイルから取得します。統合テストは Elasticsearch 8.19、9.3、9.4、9.5 をカバーします。

## Apache Doris

- Doris サービスプラグイン：カタログ、データベース、テーブル、列、ワークロードグループ。1 台以上の FE に接続し、パスワードでログインします。[Apache Doris](/ja/plugins/doris/) を参照してください。
- クラスターの横で動くエージェント：ポリシーは Doris 自身のロール、列の権限付与、ワークロードグループの権限付与、行ポリシーになり、ユーザーのすべてのアイデンティティに付与されます。データベースやカタログ全体への付与は、それによって Doris がより多くを与えない場合に限ります。[Apache Doris エージェント](/ja/external/doris-agent/) を参照してください。
- アクセスの記録は Doris の監査ログテーブルから取得します。統合テストは Doris 2.1、3.1、4.0、4.1 をカバーします。

## MongoDB

- MongoDB サービスプラグイン：データベースとコレクション。レプリカセットまたはシャードクラスターに接続し、SCRAM、クライアント証明書、LDAP、Kerberos でログインします。[MongoDB](/ja/plugins/mongodb/) を参照してください。
- デプロイメントの横で動くエージェント：ユーザーごとに MongoDB のロールを 1 つ維持し、その権限を一度に置き換えます。MongoDB が返す継承された権限から、GrantForge の外にある組み込みロールやカスタムロールが実際に何を与えているかを報告します。[MongoDB エージェント](/ja/external/mongodb-agent/) を参照してください。
- アクセスの記録は Enterprise または Percona の監査ログファイル、あるいはプロファイラーから取得します。統合テストは MongoDB 6.0、7.0、8.0、9.0 をカバーし、Kerberos は Percona Server for MongoDB で検証しています。

## Redis と Valkey

- Redis サービスプラグイン：キー、チャンネル、ノード。単体サーバーとそのレプリカ、またはクラスターに接続し、ACL ユーザーとしてログインします。TLS も使えます。[Redis](/ja/plugins/redis/) を参照してください。
- デプロイメントの横で動くエージェント：すべてのノードで各ユーザーの ACL セレクターをポリシーに合わせ、1 つのコマンドでまとめて置き換えます。ルートの権限は引き続き運用担当者が管理し、エージェントはそれがポリシーの拒否するアクセスを許していないかを `ACL DRYRUN` で Redis に確かめます。[Redis エージェント](/ja/external/redis-agent/) を参照してください。
- 拒否の記録は各ノードの ACL ログから取得します。統合テストは Redis 7.2、7.4、8.2、8.10 と Valkey 8.1、9.1、さらに Redis 8.10 のクラスターをカバーします。

## エージェント

- ClickHouse、PostgreSQL、OpenSearch のエージェントと、このリリースで加わったシステムの横で動くエージェントは、新しい `grantforge-agent-sync` コアを共有します。起動処理、設定、タイマー、同期の流れ、監査の読み取り位置、ログファイルの追跡がそこにあります。各エージェントはそのシステム固有の部分だけを持ち、設定とログの形式は変わりません。

## アイデンティティと組織

- データソース：組織構造の同期はアイデンティティソースとは別に設定し、最初のアダプターは公式のサーバー SDK を使う DingTalk です。SSO でログインしたユーザーは、信頼できるメールアドレスによって部署と主所属部署に自動で関連付けられます。そのテーブルはサポートする 6 種類すべてのデータベースで、SQL Server と Oracle も含めて移行されます。[アイデンティティソース（LDAP と OIDC）](/ja/guide/identity-sources/) を参照してください。
- OpenID Connect のアイデンティティソースは電話番号とアバターを同期でき、認可リクエストにパラメーター（Casdoor の `provider_hint` など）を追加できます。プロトコル自身のパラメーターは上書きできません。

## 認可とリソースカタログ

- ユーザーへの直接付与：業務アプリケーションのメニュー、ページ、ボタン、API を 1 人のユーザーだけに許可し、有効期限も設定できます。ロールの権限と合わせて計算され、ロールによる拒否が引き続き優先します。[ユーザー](/ja/guide/users/) を参照してください。
- リソースカタログはアプリケーションのリソースツリーを JSON としてエクスポートし、別のアプリケーションにインポートできます。インポートはまず事前チェックされ、衝突があれば何も適用されません。プラットフォーム管理者は条件を満たすアプリケーションのツリーを空にできます。[リソースカタログと API カタログ](/ja/guide/catalog/) を参照してください。

## サーバー

- 起動時には Spring Boot のバナーではなく、GrantForge のバナー、バージョン、Java のバージョンが表示されます。

## ドキュメントとリリース

- プラグインのタブは概要から始まり、システムを種類ごとに折りたためるサイドバーにまとめ、各システムの適用方式、行フィルターとマスキングへの対応、検証済みのバージョンを一覧にします。各 README も同じ順序でコンポーネントを並べます。
- CI は、すべてのページがすべての言語に完全に翻訳されていることを確認します。段落、見出し、表、コードブロック、リンクが中国語のページと一致し、ほかの言語の文字を含まず、英語のページから写した文もないことです。11 個の README も英語の README を基準に同じ確認を受けます。この確認で見つかった翻訳の不足はすべて補いました。
- バージョンの確認がすべての README のバージョンバッジを最新に保ちます。
- ドキュメントの公開とリリースのワークフローはフォークでは実行されなくなりました。
- サーバー `grantforge-server` は Maven リポジトリーに公開しなくなりました。すべてのプラグインを同梱しておりリポジトリーのサイズ上限を超えるためで、サーバーはリリースアーカイブとイメージで提供されます。

## 修正

- リソースの編集画面でリソースの種類を変えると、合わなくなったリソースコードが消去されます。
- JavaScript 連携ガイドの最後のコードブロックが後ろの本文を飲み込まなくなり、Docker とクイックスタートのページにあるコンソールのアドレスが後ろの文字をリンクにしなくなりました。
- 依存関係をセキュリティアドバイザリーを修正したバージョンに更新しました：MariaDB Connector/J 3.5.11、OpenTelemetry 1.67.0、Guava 33.7.2、Snappy 1.1.10.9、およびコンソールと SDK の vue-i18n、glob、minimatch。
