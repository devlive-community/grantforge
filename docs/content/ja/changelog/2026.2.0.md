2026.2.0 は 2026.1.0 の外部システム権限を Apache Hive、Apache Kafka、Apache HBase、Trino、Apache Hadoop YARN に拡張し、それを適用するエージェントを提供します。変更の全体は [GitHub の比較](https://github.com/devlive-community/grantforge/compare/v2026.1.0...v2026.2.0) を参照してください。

## Apache Hive

- Hive サービスプラグイン：データベース、テーブル、列、UDF、URL、HiveServer2 サービスとレプリケーション。アクセス種別は Apache Ranger の定義どおり。[Apache Hive](/ja/plugins/hive/) を参照。
- HiveServer2 エージェント：すべての文を検査し、`SHOW` の結果をフィルタし、列をマスクし、行をフィルタします。[Hive エージェント](/ja/external/hive-agent/) を参照。
- 一時 UDF はグローバルスコープで `tempudfadmin` にのみ付与されます。Apache Ranger と同様に、利用者が選んだコードを実行するためです。

## Apache Kafka

- Kafka サービスプラグイン：トピック、グループ、トランザクション ID、クラスター、委任トークン、SCRAM ユーザー。Kafka 固有のアクセス種別と含意関係を使用します。[Apache Kafka](/ja/plugins/kafka/) を参照。
- ブローカーとコントローラーの認可機能：すべてのリクエストを検査します。[Kafka エージェント](/ja/external/kafka-agent/) を参照。

## Apache HBase

- HBase サービスプラグイン：名前空間、テーブル、列ファミリー、列、およびクラスター全体の操作のためのグローバルスコープ。[Apache HBase](/ja/plugins/hbase/) を参照。
- マスターとリージョンサーバーのコプロセッサー：操作を検査し、利用者が読める列だけを返し、見えないものは隠します。[HBase エージェント](/ja/external/hbase-agent/) を参照。

## Trino

- Trino サービスプラグイン：カタログ、スキーマ、テーブル、列、関数、プロシージャ、セッションプロパティ。[Trino](/ja/plugins/trino/) を参照。
- 2 つのシステムアクセス制御：Trino 470〜478 用と Trino 479 以降用。クエリを検査し、行をフィルタし、列をマスクします。[Trino エージェント](/ja/external/trino-agent/) を参照。

## Apache Hadoop YARN

- YARN サービスプラグイン：キューとアプリケーション。YARN の `submit_app` と `admin_queue` のアクセス種別を使用します。[Apache Hadoop YARN](/ja/plugins/yarn/) を参照。
- ResourceManager の認可プロバイダー：ポリシーにより投入、キュー、クラスター管理を判定し、クライアントアドレスの条件を扱えます。[YARN エージェント](/ja/external/yarn-agent/) を参照。

## ポリシーエンジンとエージェント

- ポリシーはリソースの下位にあるアクセスを判定します。データベースの一覧表示はユーザーのテーブルポリシーを数えます。新しい `_any` アクセス種別は、リソースまたはその下位のいずれかへのアクセスが許可されていれば許可されます。
- ポリシーは、ある階層のいずれかのリソースに対してユーザーが操作できるかを答えます。Kafka が冪等プロデューサーの書き込み前に問い合わせるのと同じ仕組みです。
- エージェントは、時間枠内で同一の許可されたアクセスを、回数と最後の時刻を持つ 1 件の監査イベントにまとめます。拒否は即座に記録されます。
- エージェントは、アクセスポリシーをシステム自身の用語で表示できます。
- プラグイン API 1.2.0 は Kerberos の realm をすべてのプラグインに一度だけ提供します。これにより、Kerberos を使うプラグイン同士が互いの `krb5.conf` を上書きしなくなりました。

## ドキュメントとリリース

- YARN、Hive、Kafka、HBase、Trino のプラグインとエージェントは、11 の言語すべてで文書化されています。
- README に、サポートされるコンポーネントと、統合テストで検証されたバージョンを記載しました。
- リリースタグは完全な CI を実行し、リリースはその実行の完了を待ちます。ディストリビューションは並列でビルドされ、npm は信頼された公開（trusted publishing）で公開されます。
- リリースログのないバージョンはタグ付け時に拒否されます。CI は共通の Java ゲートの後、変更に必要なジョブだけを実行します。

## 修正

- PostgreSQL のインデックスをシード投入後に準備するようにしました。これにより、計測対象の API 呼び出しが分析済みのテーブルに対して実行されます。
- ZooKeeper エージェントの jar テストは、パッケージングの後に実行されます。
- Maven のデプロイは統合テストをスキップします。HDFS 3.2 エージェントで forked JVM がタイムアウトし、GitHub Packages へのデプロイが失敗していました。
- npm パッケージはリポジトリを宣言するようになり、npm が provenance を検証できます。
