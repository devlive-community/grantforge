2026.3.0 は外部システム権限を Apache Pulsar、Apache Solr、ClickHouse、PostgreSQL、OpenSearch に拡張します。Pulsar と Solr のエージェントはシステムの内部ですべてのリクエストを判定し、ClickHouse、PostgreSQL、OpenSearch のエージェントはシステムの隣で動いてシステム自身のアクセス制御をポリシーに合わせ続けるため、システム自身がすべてのリクエストを検査します。変更の全体は [GitHub の比較](https://github.com/devlive-community/grantforge/compare/v2026.2.0...v2026.3.0) を参照してください。

## Apache Pulsar

- Pulsar サービスプラグイン：テナント、名前空間、トピック、トピックの下のサブスクリプション、クラスター。Pulsar の produce、consume、functions、sources、sinks、packages と、トピック・名前空間・テナントの管理を使用します。トークン、パスワード、OAuth 2.0 クライアント資格情報、TLS クライアント証明書でサインインします。[Apache Pulsar](/ja/plugins/pulsar/) を参照。
- ブローカーの認可プロバイダー：各チェックをテナント、名前空間、トピック、サブスクリプションの順に判定し、クライアントアドレスの条件に対応します。クラスターの admin はロールを Pulsar のスーパーユーザーにし、Pulsar 自身による付与は拒否されます。[Pulsar エージェント](/ja/external/pulsar-agent/) を参照。
- 統合テストは Pulsar 3.0.17、3.3.9、4.0.14、4.2.5 を対象としています。

## Apache Solr

- Solr サービスプラグイン：コレクション、その中の `/select` や `/export` などのリクエストパス（ポリシーはコレクションを許可しつつ 1 つのハンドラーを拒否できます）、クラスター。基本認証または JSON Web Token でサインインします。[Apache Solr](/ja/plugins/solr/) を参照。
- ノードの認可プラグイン：Solr のルールベースのプラグインと同じようにリクエストを分類し、それぞれをコレクションとリクエストパスで判定します。Collections API のリクエストには指定するすべてのコレクションに `admin_collection` が必要で、JSON Web Token の検証済みロールはグループとして扱われます。[Solr エージェント](/ja/external/solr-agent/) を参照。
- 統合テストは Solr 9 のセキュリティマネージャーの下で、Solr 9.8.1、9.10.1、9.11.0、10.0.0 の SolrCloud ノードを対象としています。

## ClickHouse

- ClickHouse サービスプラグイン：データベース、テーブル、列、サーバー。読み取りと書き込みは列ごとに、テーブル・データベース・サーバーの操作はそれぞれのアクセス種別で判定します。いずれも権限グループではないため、ポリシーが指定した以上を与えることはありません。[ClickHouse](/ja/plugins/clickhouse/) を参照。
- サーバーの隣で動くエージェント：ユーザーごとにポリシーが与えるものだけを持つロールを 1 つ、行フィルターごとに行ポリシーを 1 つ保ちます。データベース全体で許可され、その下に制限のないアクセス種別はデータベースに付与されるため、新しいテーブルにもすぐに適用されます。[ClickHouse エージェント](/ja/external/clickhouse-agent/) を参照。
- アクセスは `system.query_log` から報告され、GrantForge の外でポリシーが拒否するものを与える付与は警告されます。統合テストは ClickHouse 24.8、25.3、25.8、26.3、26.8 を対象としています。

## PostgreSQL

- PostgreSQL サービスプラグイン：データベース、スキーマ、テーブルとビュー、列。PostgreSQL の権限を PostgreSQL が付与する階層で判定します。パスワードまたは TLS クライアント証明書でサインインし、libpq の TLS モードを使用します。[PostgreSQL](/ja/plugins/postgresql/) を参照。
- サーバーの隣で動くエージェント：各データベースでユーザーごとにロールを 1 つ、列まで保ち、必要な `CONNECT`、スキーマの `USAGE`、serial シーケンスを付与し、各データベースを 1 つのトランザクションで変更します。行フィルターは制限的な行セキュリティポリシーになり、絞り込むだけです。[PostgreSQL エージェント](/ja/external/postgresql-agent/) を参照。
- アクセスは pgaudit で書かれたサーバーログから報告されます。統合テストは PostgreSQL 15、16、17、18 を対象としています。

## OpenSearch

- OpenSearch サービスプラグイン：インデックスとデータストリーム、そのフィールド、クラスター。各アクセス種別はセキュリティプラグインのアクショングループで、マスクはそのマスクフィールドに、行フィルターはドキュメントレベルセキュリティになります。[OpenSearch](/ja/plugins/opensearch/) を参照。
- クラスターの隣で動くエージェント：ユーザーごとにそのユーザーだけに対応付けたロールを 1 つ保ち、セキュリティプラグインがクラスター全体に適用する JSON パッチとして書き込みます。すべてのポリシーが同じ判定をするインデックスパターンはパターンのまま残るため、後から作られたインデックスにもすぐに届きます。[OpenSearch エージェント](/ja/external/opensearch-agent/) を参照。
- アクセスはセキュリティプラグインの監査ログから報告され、GrantForge の外でポリシーが拒否するものを与えるロールは警告されます。統合テストは OpenSearch 2.19、3.3、3.6、3.9 を対象としています。

## ポリシーエンジンとエージェント

- ポリシーエンジンは、リソースの下位にあるものがユーザーとアクセスに対して異なる判定を受けうるかを判定します。そのため、システム自身の用語で付与するエージェントは、データベースのすべてのテーブルのように、コンテナー全体を付与できます。
- エージェントのスナップショットは、アクセスポリシーに加え、マスクと行フィルターのポリシー、およびそれらが指すユーザーを示します。

## ドキュメントとリリース

- Pulsar、Solr、ClickHouse、PostgreSQL、OpenSearch のプラグインとエージェントは 11 の言語すべてで文書化され、各 README に統合テストで検証されたバージョンとともに記載されています。
- ドキュメントのスクロールバーは、ライトテーマとダークテーマの両方でサイトの配色に合わせます。
- GitHub のリリースはバージョンタグをタイトルにします。

## 修正

- Pulsar プラグインは、接続を拒否するブローカーを到達できないと報告します。
- Solr エージェントは、以前のリリースのセキュリティアドバイザリーが修正された Solr 9.10.1 でビルドされます。
- PostgreSQL エージェントは、サーバーログの時刻にある `CEST` などのタイムゾーン略称を読み取ります。
- OpenSearch エージェントは SLF4J を自身の jar の中に保つため、これを同梱するサーバーは自身のログ設定を保ちます。
- コンソール、SDK、ドキュメントサイトは、vite、vitest、undici、dompurify を npm のアドバイザリーを修正したリリースに更新しました。
