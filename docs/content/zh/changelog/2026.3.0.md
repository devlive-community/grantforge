2026.3.0 将外部系统权限扩展到 Apache Pulsar、Apache Solr、ClickHouse、PostgreSQL 与 OpenSearch。Pulsar 与 Solr 代理在系统内部判定每个请求；ClickHouse、PostgreSQL 与 OpenSearch 代理运行在系统旁边，让系统自身的访问控制与策略保持一致，由系统自己检查每个请求。完整变更见 [GitHub 对比](https://github.com/devlive-community/grantforge/compare/v2026.2.0...v2026.3.0)。

## Apache Pulsar

- Pulsar 服务插件：租户、命名空间、主题、主题下的订阅与集群，使用 Pulsar 的 produce、consume、functions、sources、sinks、packages 以及主题、命名空间与租户的管理访问类型；支持令牌、密码、OAuth 2.0 客户端凭据或 TLS 客户端证书登录；见 [Apache Pulsar](/plugins/pulsar/)。
- Broker 授权提供者：依次在租户、命名空间、主题与订阅上判定每次检查，并支持客户端地址条件；集群上的 admin 使角色成为 Pulsar 超级用户，通过 Pulsar 自身授权会被拒绝；见 [Apache Pulsar 代理](/external/pulsar-agent/)。
- 集成测试覆盖 Pulsar 3.0.17、3.3.9、4.0.14 与 4.2.5。

## Apache Solr

- Solr 服务插件：集合、集合内的请求路径（如 `/select`、`/export`，策略可以允许集合而拒绝某个处理器）以及集群；支持基本认证或 JSON Web Token 登录；见 [Apache Solr](/plugins/solr/)。
- 节点授权插件：按 Solr 基于规则的插件的方式对请求分类，并在集合与请求路径上逐一判定；Collections API 请求需要对其涉及的每个集合拥有 `admin_collection`，JSON Web Token 中经过验证的角色视为用户组；见 [Apache Solr 代理](/external/solr-agent/)。
- 集成测试在 Solr 9 的安全管理器下覆盖 Solr 9.8.1、9.10.1、9.11.0 与 10.0.0 的 SolrCloud 节点。

## ClickHouse

- ClickHouse 服务插件：数据库、表、列与服务器；读写按列判定，表、数据库与服务器的操作使用各自的访问类型，均不是权限组，因此策略不会给出超出其所列的权限；见 [ClickHouse](/plugins/clickhouse/)。
- 运行在服务器旁的代理：为每个用户维护一个恰好包含策略所授权限的角色，并为每个行过滤器维护一条行策略；在整个数据库上允许且其下没有任何限制的访问类型会授予在数据库上，新表立即可用；见 [ClickHouse 代理](/external/clickhouse-agent/)。
- 访问记录来自 `system.query_log`；GrantForge 之外给出了策略所拒绝权限的授权会被报告。集成测试覆盖 ClickHouse 24.8、25.3、25.8、26.3 与 26.8。

## PostgreSQL

- PostgreSQL 服务插件：数据库、模式、表与视图以及列，权限在 PostgreSQL 授予它们的层级上判定；支持密码或 TLS 客户端证书登录，并使用 libpq 的 TLS 模式；见 [PostgreSQL](/plugins/postgresql/)。
- 运行在服务器旁的代理：在每个数据库中为每个用户维护一个角色，细化到列，并附带所需的 `CONNECT`、模式 `USAGE` 与 serial 序列，每个数据库的变更在一个事务中完成；行过滤器成为限制性行安全策略，只会收窄访问；见 [PostgreSQL 代理](/external/postgresql-agent/)。
- 访问记录来自 pgaudit 写入的服务器日志。集成测试覆盖 PostgreSQL 15、16、17 与 18。

## OpenSearch

- OpenSearch 服务插件：索引与数据流、其字段以及集群；每种访问类型都是安全插件的一个动作组；屏蔽成为其屏蔽字段，行过滤器成为其文档级安全；见 [OpenSearch](/plugins/opensearch/)。
- 运行在集群旁的代理：为每个用户维护一个仅映射到该用户的角色，以 JSON 补丁写入，安全插件会在整个集群生效；凡是所有策略对其判定一致的索引模式都保持为模式，之后创建的索引立即可达；见 [OpenSearch 代理](/external/opensearch-agent/)。
- 访问记录来自安全插件的审计日志；GrantForge 之外给出了策略所拒绝权限的角色会被报告。集成测试覆盖 OpenSearch 2.19、3.3、3.6 与 3.9。

## 策略引擎与代理

- 策略引擎可以判断资源之下是否有内容会对某用户和某访问作出不同判定，因此以系统自身术语授权的代理可以整体授予容器，例如数据库中的所有表。
- 代理快照除访问策略外，还提供屏蔽与行过滤策略以及其中涉及的用户。

## 文档与发布

- Pulsar、Solr、ClickHouse、PostgreSQL 与 OpenSearch 的插件和代理已提供全部 11 种语言的文档，各 README 均列出它们及集成测试验证的版本。
- 文档站的滚动条在浅色与深色主题下都跟随站点配色。
- GitHub 发布以版本标签作为标题。

## 问题修复

- Pulsar 插件将拒绝连接的 Broker 报告为无法访问。
- Solr 代理基于 Solr 9.10.1 构建，该版本修复了早期版本的安全公告。
- PostgreSQL 代理可以解析服务器日志时间中的时区缩写，如 `CEST`。
- OpenSearch 代理将 SLF4J 保留在自己的 jar 内，打包它的服务器保持自身的日志配置。
- 控制台、SDK 与文档站将 vite、vitest、undici 与 dompurify 升级到修复 npm 安全公告的版本。
