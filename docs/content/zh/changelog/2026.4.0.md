2026.4.0 将外部系统权限扩展到 Elasticsearch、Apache Doris、MongoDB 以及 Redis 与 Valkey，四个代理都运行在系统旁边，让系统自身的访问控制与策略保持一致。身份与授权方面新增钉钉组织架构同步、用户直接授权和资源目录的导入导出。完整变更见 [GitHub 对比](https://github.com/devlive-community/grantforge/compare/v2026.3.0...v2026.4.0)。

## Elasticsearch

- Elasticsearch 服务插件：索引与数据流、其字段以及集群；支持密码、API 密钥或 TLS 客户端证书登录；见 [Elasticsearch](/plugins/elasticsearch/)。
- 运行在集群旁的代理：为每个用户维护 Elasticsearch 自己的角色，赋予原生用户，并通过角色映射给其他 realm 的用户；许可证允许时带有字段级与文档级安全；索引模式保持为模式，新索引立即可用；见 [Elasticsearch 代理](/external/elasticsearch-agent/)。
- 访问记录来自审计日志文件。集成测试覆盖 Elasticsearch 8.19、9.3、9.4 与 9.5。

## Apache Doris

- Doris 服务插件：Catalog、数据库、表、列与工作负载组；连接一个或多个 FE，以密码登录；见 [Apache Doris](/plugins/doris/)。
- 运行在集群旁的代理：策略成为 Doris 自己的角色、列授权、工作负载组授权与行策略，并授予用户的每个身份；只有在 Doris 不会因此给出更多权限时，才授予整个数据库或 Catalog；见 [Apache Doris 代理](/external/doris-agent/)。
- 访问记录来自 Doris 的审计日志表。集成测试覆盖 Doris 2.1、3.1、4.0 与 4.1。

## MongoDB

- MongoDB 服务插件：数据库与集合；连接副本集或分片集群，支持 SCRAM、客户端证书、LDAP 或 Kerberos 登录；见 [MongoDB](/plugins/mongodb/)。
- 运行在部署旁的代理：为每个用户维护一个 MongoDB 角色，一步替换其权限；通过 MongoDB 给出的继承权限，报告 GrantForge 之外的内置与自定义角色实际给了什么；见 [MongoDB 代理](/external/mongodb-agent/)。
- 访问记录来自 Enterprise 或 Percona 的审计日志文件，或来自 Profiler。集成测试覆盖 MongoDB 6.0、7.0、8.0 与 9.0，Kerberos 在 Percona Server for MongoDB 上验证。

## Redis 与 Valkey

- Redis 服务插件：键、频道与节点；连接单机及其副本或集群，以 ACL 用户登录，可选 TLS；见 [Redis](/plugins/redis/)。
- 运行在部署旁的代理：在每个节点上让每个用户的 ACL 选择器与策略保持一致，并用一条命令整体替换；根权限仍由运维人员管理，代理用 `ACL DRYRUN` 询问 Redis 这些权限是否允许了策略拒绝的访问；见 [Redis 代理](/external/redis-agent/)。
- 拒绝记录来自各节点的 ACL 日志。集成测试覆盖 Redis 7.2、7.4、8.2、8.10 与 Valkey 8.1、9.1，以及一个 Redis 8.10 集群。

## 代理

- ClickHouse、PostgreSQL、OpenSearch 以及本版新增的系统旁代理共用新的 `grantforge-agent-sync` 核心：启动器、设置、定时器、同步流程、审计读取位置与日志文件跟踪；各代理只保留其系统特有的部分，设置与日志格式不变。

## 身份与组织

- 数据源：组织架构同步独立于身份源配置，首个适配器为钉钉，使用其官方服务端 SDK；用户通过 SSO 登录后按可信邮箱自动关联部门与主部门；其数据表在全部六种支持的数据库上迁移，包括 SQL Server 与 Oracle；见 [身份源](/guide/identity-sources/)。
- OpenID Connect 身份源可以同步手机号与头像，并可在授权请求中附加参数（例如 Casdoor 的 `provider_hint`），协议自身的参数不能被覆盖。

## 授权与资源目录

- 用户直接授权：为单个用户允许业务应用的菜单、页面、按钮或接口，可设置到期时间，与角色权限一起计算，角色中的拒绝仍然优先；见 [用户](/guide/users/)。
- 资源目录可以把应用的资源树导出为 JSON，再导入另一个应用：先预检，冲突时整个导入不生效；平台管理员可以清空符合条件的应用资源树；见 [资源目录](/guide/catalog/)。

## 服务端

- 启动时打印 GrantForge 的横幅、版本与 Java 版本，不再是 Spring Boot 的横幅。

## 文档与发布

- 插件页以总览开始，按系统类型分组并可折叠，列出每个系统的执行方式、行过滤与脱敏支持以及验证过的版本；各 README 按同样的顺序列出组件。
- CI 检查每个页面在每种语言中的翻译是否完整：段落、标题、表格、代码块与链接与中文页一致，不含其他语言的文字，也不照抄英文页；11 个 README 按英文 README 做同样的检查。检查发现的缺失翻译已全部补齐。
- 所有 README 的版本徽章都由版本检查维护。
- 在 fork 上不再运行发布文档与发布版本的工作流。
- 服务端 `grantforge-server` 不再发布到 Maven 仓库：它包含全部插件，超出了仓库的大小限制；服务端随发行包与镜像提供。

## 问题修复

- 在资源编辑框中改变资源类型时，清除不再适用的资源编码。
- JavaScript 接入指南的最后一个代码块不再吞掉后面的正文，Docker 与快速开始页面中的控制台地址不再把后面的文字当作链接。
- 依赖升级到修复安全公告的版本：MariaDB Connector/J 3.5.11、OpenTelemetry 1.67.0、Guava 33.7.2、Snappy 1.1.10.9，以及控制台与 SDK 中的 vue-i18n、glob 与 minimatch。
